Chapter 4 所要時間: 60〜90 分 形式: ローカルにフロントを保存 + Colab サーバへ繋ぐ

第 4 章 — フロントを足して、 ガチャ画面を呼ぶ

Ch.3 で REST クライアント (Hoppscotch など) から Colab サーバを叩けました。 でもこれは「開発者が手で API を叩いている」 状態で、 まだゲーム画面ではない。 この章で本物のフロント (ガチャ画面) を手元のブラウザで開いて、 Colab サーバと繋ぎます。

📐 進め方
  • フロント (HTML/CSS/JS) は既製品を渡します。 自分で書く必要なし
  • 手元の PC にダウンロードして、 index.html をダブルクリックするだけで動く
  • サーバは Ch.3 のまま Colab で起動。 Colab 公開 URL をフロントの設定欄に入れる
  • 「ブラウザに表示されるゲーム画面 ⇄ Colab 上の Python サーバ ⇄ SQLite」 が一気通貫で動く

4.1 そもそもフロントとは

Ch.0 でちらっと触れましたが、 改めて。 フロントエンド = ユーザーが直接触る画面のこと。 Web の場合は次の 3 種類のファイルでできています:

  • .html = ページの骨組み (見出し / フォーム / ボタン 等)
  • .css = 見た目 (色 / 余白 / レイアウト)
  • .js = 動き (ボタンを押したら何をするか、 サーバへ通信、 など)

ブラウザに .html を開かせると、 ブラウザが中身を読んで .css と .js も 自動的に取りに行って画面が組み上がります。 今読んでいるこの教材ページもまさにそれ。

4.2 配布フロントを 3 ファイル取得する

本リポジトリの web/ フォルダに、 ガチャ画面の HTML / CSS / JS が一式置いてあります。 下記の 3 ファイルをダウンロードして、 手元の PC の好きなフォルダ (例: ~/Downloads/gacha_web/) にまとめて保存してください。

  • web/index.html
  • web/app.js
  • web/style.css
📝 ダウンロードのコツ

上のリンクは raw ファイルへ直リンクしているので、 ブラウザで開いた状態で 右クリック → 「名前を付けてリンク先を保存」 で OK。 3 ファイルとも同じフォルダに入れること (HTML から相対パスで CSS/JS を読むため)。

まだリポジトリを公開していない人は、 リポジトリをクローンしてから web/ フォルダの中身を任意の場所にコピーしてください。

4.3 index.html をダブルクリックで開く

保存した index.html をファイルマネージャでダブルクリック → ブラウザが起動して ガチャ画面が出ます。 アドレスバーは file:///Users/.../gacha_web/index.html のような形になります (= 「ローカルファイルをそのまま見ている」 状態)。

📚 コラム: file:// って何?

URL のスキーム (Ch.1 の URL 構造コラム参照) には http/https 以外に file というものがあって、 ネットワーク越しではなく自分のディスクから直接ファイルを読む という意味です。 ローカルで HTML を試すときの一番手軽な方法。

本格運用では file:// は使わず、 必ず Web サーバ経由で http:// で配信しますが、 今はまだ「フロントを動かしたい」 だけなのでこれで十分。

画面の上部に「API」 と書かれた入力欄、 「疎通確認」 ボタン、 画面下部に「🔍 デバッグコンソール」 が常設されているのが特徴の学習モードフロントです。

4.5 「疎通確認」 を押してみる — ここでつまずく可能性大

フロントの「疎通確認」 ボタンをクリック。 デバッグコンソールに何かが流れるはずですが、 多くの場合赤いエラー が出ます。

⚠️ デバッグコンソールでよく起きること (1 回目) 
22:30:15 GET /api/me → NETWORK 25ms
   ⚠️ ネットワークエラー
   Failed to fetch
   → サーバが起動しているか / API URL が正しいか確認してください

原因の多くは CORS です。 ここで Web 開発の難所の 1 つに当たります。

📚 コラム: CORS (Cross-Origin Resource Sharing) とは

ブラウザは安全のため、 「あるオリジンで読み込まれた JavaScript が、 別のオリジンへ勝手に通信するのを止める」 というルールを持っています。 これが 同一オリジンポリシー。

ここで言う オリジン = スキーム + ホスト + ポート の組。 例えば:

  • http://localhost:5500 と http://localhost:8000 は違うオリジン (ポート違い)
  • file://... は「null」 という特別なオリジンとして扱われる
  • file://... から https://abcd.colab.googleusercontent.com へ fetch する → これもクロスオリジンでブラウザが標準で止める

止められないようにするには、 サーバ側が応答ヘッダで明示的に 「自分はこのオリジンからのアクセスを許可します」 と宣言する必要があります。 これが Access-Control-Allow-Origin。

本教材では学習用に「誰からでも OK」 (Access-Control-Allow-Origin: *) で開けます。 本番ではちゃんと許可元を絞ります。

4.6 サーバの CORS を緩める

Ch.1 で書いた App クラスの _cors メソッドを丸ごと書き換えます。 Colab で Ch.1 のセル 1-G の App を再定義するつもりで、 以下のセルを実行:

📒 セル (Colab) — CORS を全許可にして再定義 
import json, traceback
from urllib.parse import urlparse
from http.server import BaseHTTPRequestHandler

class App(BaseHTTPRequestHandler):
    def do_GET(self):     self._dispatch("GET")
    def do_POST(self):    self._dispatch("POST")
    def do_OPTIONS(self):
        # プリフライトリクエストへの応答
        self.send_response(204)
        self._cors()
        self.send_header("Content-Length", "0")
        self.end_headers()

    def _dispatch(self, method):
        path = urlparse(self.path).path
        handler = ROUTES.get((method, path))
        if handler is None:
            return self._json(404, {"error": "Not Found", "path": path})
        try:
            handler(self)
        except AppError as e:
            self._json(e.status, {"error": e.message})
        except Exception as e:
            traceback.print_exc()
            self._json(500, {"error": "internal server error", "detail": str(e)})

    def _cors(self):
        # 学習用: 全オリジン許可 (= 誰からでも叩いて OK)
        self.send_header("Access-Control-Allow-Origin",  "*")
        self.send_header("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
        self.send_header("Access-Control-Allow-Headers", "Content-Type")

    def _read_json(self):
        n = int(self.headers.get("Content-Length", "0"))
        raw = self.rfile.read(n) if n else b""
        try:
            return json.loads(raw.decode("utf-8")) if raw else {}
        except json.JSONDecodeError as e:
            raise bad_request(f"invalid json: {e}")

    def _text(self, status, body):
        b = body.encode("utf-8"); self.send_response(status); self._cors()
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False, default=str).encode("utf-8")
        self.send_response(status); self._cors()
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args): pass

# 再起動 (Ch.1 の serve helper をそのまま使える)
serve(App)
print("CORS 緩和済みのサーバが立ち上がりました")

💡 解説

  • 追加点 1: do_OPTIONS = ブラウザが本リクエストの前に投げる 「プリフライト」 への返事。 「このオリジン、 このメソッド、 このヘッダで通信していい?」 を聞かれるので、 OK のヘッダだけ付けて中身なしで返す
  • 追加点 2: Access-Control-Allow-Origin: * = 全オリジン許可
  • _cors を全レスポンス (200/JSON/エラー含む) で呼ぶようにしている

4.7 もう一度「疎通確認」 を押す

フロントの画面に戻って、 もう一度「疎通確認」 を押してみる。

✅ 期待される結果
  • API ステータスインジケータ (●) が緑になる
  • デバッグコンソール: GET /api/me → 401 もしくは 404 (= サーバから何かが返ってきている)
  • これで手元のブラウザと Colab のサーバが会話できる状態

これが今日の山場です。 「自分の PC のブラウザ」 が「Colab で動く Python サーバ」 と 話している。 オリジンを越えて、 file:// から HTTPS の Colab URL まで、 リクエスト 1 本が通った。

4.8 ガチャ画面に直接入る — まずは「ゲスト」 として遊ばせる

フロントは起動時に GET /api/me を叩きます。 これに「あなたはログイン中の○○さん」 と 返してあげると、 フロントは登録/ログイン画面をスキップしてガチャ画面に直行します。

ユーザー登録 / ログイン / セッション管理は Ch.7 でちゃんと作りますが、 まずはガチャを動かしたいので、 /api/me を「仮の guest ユーザー」 を返す形にしておきます。 この仮実装が Ch.7 で本物に置き換わるイメージ。

📒 セル (Colab) — /api/me を guest 返却に 
@route("GET", "/api/me")
def me(h):
    # 仮: 全員 guest ユーザーとして扱う。 Ch.7 で本物の認証に置き換える。
    h._json(200, {"user": {
        "id": 1, "name": "guest", "display_name": "ゲスト", "coins": 1000,
    }})

print("✅ /api/me が guest ユーザーを返すように")

ブラウザをリロードしてください。

🎉 期待される結果
  • デバッグコンソール: GET /api/me → 200 ✓ 期待形式 (緑)
  • 画面: 登録フォームを飛ばして、 そのままガチャ画面が出る (「ようこそ ゲスト さん」)
  • 「引く」 ボタン押下 → ハードコードのドラゴンが出る (まだ Ch.4 の 404)

4.9 残り API もハードコードで通す — フロント全機能を埋める

ガチャ一覧 / 引く / Box の 3 API もハードコードで形だけ満たします。 中身はまだ DB を見ていないので 必ずドラゴンが出ますが、 フロントの全画面遷移が確認できる状態に。

📒 セル (Colab) — 残り API のハードコード版 
@route("GET", "/api/gacha/list")
def gacha_list(h):
    h._json(200, {"gachas": [
        {"id": 1, "name": "通常ガチャ",      "price": 100, "pool_size": 12, "total_weight": 505},
        {"id": 2, "name": "プレミアムガチャ", "price": 300, "pool_size":  7, "total_weight": 175},
    ]})

@route("POST", "/api/gacha/pull")
def gacha_pull(h):
    body = h._read_json()
    h._json(200, {
        "gacha":     {"id": body.get("gacha_id", 1), "name": "通常ガチャ", "price": 100},
        "character": {"id": 10, "name": "ドラゴン", "rarity": 5, "emoji": "🐉"},
        "obtained_at": "2026-04-27 12:00:00",
        "coins": 900,
    })

@route("GET", "/api/box")
def box(h):
    h._json(200, {
        "user": {"id": 1, "name": "guest", "display_name": "ゲスト", "coins": 900},
        "total_pulls": 1,
        "items": [{
            "id": 10, "name": "ドラゴン", "rarity": 5, "emoji": "🐉", "count": 1,
            "first_obtained_at": "2026-04-27 12:00:00",
            "last_obtained_at":  "2026-04-27 12:00:00",
        }],
    })

print("✅ フロントの全機能をハードコードで埋めた")
print("ルート一覧:", sorted(ROUTES))

ブラウザでフロントをリロード → ガチャ画面 → 「引く」 押下。 必ずドラゴンが出ます 。 Box にもドラゴンが入る。 デバッグコンソール全緑。

4.10 ハードコードの限界と次章への動機

  • 引くたびに毎回ドラゴン。 weight も乱数も無視されている
  • コインは 1000 → 900 で固定、 何回引いても変わらない
  • Box は固定 1 体。 引いても増えない
  • 登録もログインもなく「ゲスト」 として遊んでいる状態 (これは Ch.7 で改善)

でも仕組みとしては、 フロントが期待する全 API が「形を満たしている」 状態が確保できました。 残るは「中身を本物にする」 だけ。 これを Ch.5〜7 でステップを刻んでやっていきます。

本章のまとめ

  • フロント (HTML/CSS/JS) は既製品を手元に保存して、 file:// で開ける
  • ブラウザは異なるオリジンへの fetch を止める = CORS。 サーバに Access-Control-Allow-Origin: * + OPTIONS 対応を追加すれば通る
  • Colab 公開 URL をフロントの API 設定欄に入れれば、 手元の PC ⇄ Colab で会話成立
  • API がハードコードでも、 「形が合っていれば」 フロントは動く。 中身は後でいい
