イントロ — HTTP は「ヘッダ + 空行 + 本文」のテキスト

クライアントが手紙を 1 通送り、サーバーが返事を 1 通返す。手紙の中身はただのテキストです。 

POST /api/login HTTP/1.1
Host: localhost:8000
Content-Type: application/json
Content-Length: 39

{"name":"alice","password":"secret"}
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Length: 32

{"user":{"id":1,"name":"alice"}}

Web の上で動くもの全て、結局はこの形のテキストの上に積み上がっています。

📚 コラム: URL の構造 / localhost / ポート番号

HTTP リクエストの 1 行目には URL のパス部分 が入っていました。 では URL 全体は どんな構造をしているのか? 

https://example.com:443/api/users?id=1#top
└┬─┘   └─────┬─────┘└┬┘└────┬────┘└─┬─┘└┬┘
スキーム  ホスト    ポート  パス    クエリ フラグメント
  • スキーム: http or https (暗号化付き)。 他に ftp, file, ws 等あるが Web では実質この 2 つ
  • ホスト: 通信相手のマシン名。 example.com のような ドメイン名は DNS で IP アドレスに変換される
  • ポート番号: 同じマシンに複数のサーバが立っているとき、 番号で識別する (= ビルの号室番号みたいなもの)。 0〜65535 の整数。 1024 未満は OS 予約 (HTTP=80、 HTTPS=443、 SSH=22 等)。 自作サーバは 1024 以上を使う (例: 8000、 5500)
  • パス: サーバ上のリソース位置。 これが Ch.1 で見ている self.path
  • クエリ: ?key=value&k2=v2 形式の追加パラメータ。 Step 3 で parse_qs で分解した
  • フラグメント: ページ内アンカー。 サーバには送られず、 ブラウザだけが見る

localhost は 「自分のマシン自身」 を指す特別な名前で、 IP アドレスでは 127.0.0.1 (IPv4) または ::1 (IPv6)。 他の人からは見えず、 自分のマシン内だけで完結する通信に使います。 開発中の通常の宛先。

Ch.1 のサーバは http://127.0.0.1:8000 (= http://localhost:8000) で待ち受けていますが、 これは「自分のマシンの 8000 番ポートに、 暗号化なしの HTTP で繋ぐ」 という意味。

📚 コラム: HTTP ステータスコード — 数字 3 桁の意味

Step 1 や Step 2 で self.send_response(200) と書きました。 この 3 桁の数字を HTTP ステータスコードと呼び、 「サーバがクライアントに何を伝えたいか」 を ザックリ表します。 1 桁目で大別すると:

範囲意味代表例
1xx情報 (めったに見ない)100 Continue
2xx成功 200 OK (普通の成功)、 201 Created (作った)、 204 No Content (返事だけ、 中身なし)
3xxリダイレクト301 Moved Permanently、 302 Found、 304 Not Modified
4xxクライアントが悪い 400 Bad Request (リクエスト不正)、 401 Unauthorized (未ログイン)、 403 Forbidden (権限なし)、 404 Not Found (パスが無い)、 418 I'm a teapot (お茶目)
5xxサーバが悪い 500 Internal Server Error (バグ)、 502 Bad Gateway、 503 Service Unavailable

覚え方: 4xx は「あなたのリクエストの問題」、 5xx は「サーバ側のバグ」。 ログを見たとき 5xx が出ていたら自分のコードを疑い、 4xx ならクライアント (= フロントや REST クライアント) の送り方を疑う、 というのが基本の切り分け。

本教材で頻出するのは: 200 / 400 / 401 / 404 / 500 の 5 つです。 それ以外は出てきたときに調べれば十分。

📚 ヒント: ブラウザの DevTools (開発者ツール) の Network タブ

ブラウザは すべての HTTP 往復を全部記録 していて、 開発者ツールから覗けます。 本教材では Ch.4 以降で重要になります。

  • 開き方: ブラウザのページ上で 右クリック → 「検証」 (Inspect) → 上タブの「Network」 (Chrome / Edge) または「ネットワーク」 (Firefox)
  • キーボードショートカット: macOS は ⌥⌘I、 Windows/Linux は Ctrl+Shift+I
  • ページを再読み込みすると、 そのページが投げた HTTP リクエストが全部一覧で出る
  • 1 行クリック → リクエストヘッダ、 レスポンスヘッダ、 ステータスコード、 ボディ、 所要時間 が見える

本教材の学習モードフロント (Ch.4 で登場) には独自のデバッグコンソールが付いていますが、 Network タブはそれと同じ情報を あらゆる Web サイトで見られる汎用ツール。 覚えておくと普段使うサイトの裏側も丸見えになります。

📚 参考: HTTP の下にある TCP — 雰囲気だけ知っておく

HTTP は「テキストのフォーマット規則」で、実際にバイト列を運ぶのは TCP です。 OS から見ると「IP + ポート」 で待ち受けるソケットを開き、 そこに飛んできたバイトを読んで返事を書く処理。 Python の socket モジュールでそのまま書くと、 以下のような 10 行ぐらいになります (動かす必要はありません、雰囲気だけ): 

import socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.bind(("127.0.0.1", 9000))
s.listen()
conn, _ = s.accept()
print(conn.recv(4096).decode())   # ← HTTP リクエストの生テキストが見える
conn.sendall(b"HTTP/1.1 200 OK\r\nContent-Length: 5\r\n\r\nhello")
conn.close()

実務でこんな低レイヤから書くことはまずありません。 以降は Python 標準の http.server がこの面倒を肩代わりしてくれる前提で進めます。 「HTTP は結局テキスト、その下は TCP のバイト列」 — これだけ覚えておけば十分です。

準備 — サーバを serve(App) 1 行で起動できるようにする

Notebook 内で何度もサーバを立てたり止めたりするので、それを 1 行で扱えるヘルパを置きます。 これは「育てていくサーバ本体」ではなく、Colab で快適に試行錯誤するための周辺ツールです。

📒 セル 1-A Colab で + コード を押し、新しいセルを追加。コード右上の Copy ボタンでコピーして貼り付け、 Shift + Enter。 
import threading, urllib.request, urllib.error, json, time
from http.server import HTTPServer

# 直前に立てたサーバを格納する。新しいサーバを立てる前に止めるため。
_running = []

def serve(handler_cls, port=8000):
    """前のサーバを止め、handler_cls で新しいサーバを起動する。"""
    while _running:
        s = _running.pop()
        s.shutdown()             # serve_forever ループを止める
        try: s.server_close()    # ソケットを解放してポートを空ける
        except Exception: pass
    server = HTTPServer(("127.0.0.1", port), handler_cls)
    _running.append(server)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    time.sleep(0.1)
    print(f"listening on http://127.0.0.1:{port}")
    return server

def hit(method, path, payload=None, port=8000):
    """サーバに HTTP リクエストを 1 回投げて、(status, body文字列) を返す。"""
    req = urllib.request.Request(
        f"http://127.0.0.1:{port}{path}",
        data=json.dumps(payload).encode() if payload is not None else None,
        headers={"Content-Type": "application/json"} if payload is not None else {},
        method=method)
    try:
        r = urllib.request.urlopen(req)
        return r.status, r.read().decode()
    except urllib.error.HTTPError as e:
        return e.code, e.read().decode()

print("OK: serve() / hit() ready")

from http.server import BaseHTTPRequestHandler

class App(BaseHTTPRequestHandler):

Step 3 — パス分岐を増やす

self.path を見て、 / なのか /api/health なのかで応答を変える。 ルーティングの素朴版です。

📒 セル 1-D 
from urllib.parse import urlparse, parse_qs
import json

class App(BaseHTTPRequestHandler):
    def do_GET(self):
        url = urlparse(self.path); path = url.path; q = parse_qs(url.query)
        if path == "/":
            return self._text(200, "hello, http\n")
        if path == "/api/health":
            return self._json(200, {"status": "ok"})
        if path == "/api/echo":
            return self._json(200, {"you_said": q.get("msg", [""])[0]})
        return self._json(404, {"error": "Not Found", "path": path})

    def _text(self, status, body):
        b = body.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b)))
        self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b)))
        self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args): pass

📚 コラム: そもそも JSON とは?

JSON (JavaScript Object Notation) は、 構造化データを 「人間が読めるテキスト」として表現する形式です。 由来は 2000 年代前半に Douglas Crockford が広めたもので、 JavaScript のオブジェクトリテラル構文を抜き出して 言語を問わず使える書式に整えた、 という出自。 現在は ECMA-404 / RFC 8259 として標準化されています。

仕様の核 (これだけ覚えておけば 99% 困らない)

JSON で表せる値は 6 種類 しかありません:

  • "文字列" (二重引用符必須。 シングルクォートは不可)
  • 123, 3.14, -5 等の数値 (整数と実数の区別なし。 NaN / Infinity は不可)
  • true / false
  • null
  • [ 値, 値, ... ] = 配列
  • { "キー": 値, ... } = オブジェクト (キーは必ず文字列)

つまり「ネストできるリスト/辞書 + 4 種のリテラル」 だけ。 これだけで世界中のあらゆる構造化データが表現されています。

JSON が広く使われている理由

  • 軽い: XML より圧倒的に冗長性が少ない (タグ閉じが要らない)
  • 言語非依存: ほぼすべての言語に標準/準標準のパーサーがある (Python は json、 JS はそのまま)
  • 機械可読 + 人間可読: そのままターミナルに出して読める
  • web 黎明期からの慣性: REST API の事実上の標準応答フォーマット

使われどころ

  • HTTP API のリクエスト/レスポンスボディ: 本教材の主役
  • 設定ファイル (例: package.json, VS Code の settings.json)。 ただし「コメントが書けない」 ため、 JSON5 や JSONC といった 派生形式が使われることもある
  • NoSQL の格納形式 (例: MongoDB BSON、 PostgreSQL の jsonb 列)
  • JWT (JSON Web Token) — 認証で使われる短いトークン形式

JSON でハマりやすい所

  • シングルクォート不可: {'a': 1} は不正な JSON。 必ず {"a": 1}
  • 末尾カンマ不可: [1, 2, 3,] は不正
  • コメント不可: // hello や /* ... */ は不正
  • キーは必ず文字列: {1: "a"} は不正 ({"1": "a"} なら OK)
  • 整数の精度: 仕様上は無限精度だが、 多くの実装は IEEE 754 double の範囲 (≈ 253) を超えると桁落ちする
  • 日時型は無い: ISO 8601 文字列 ("2026-04-27T06:30:00Z") で渡すのが慣例

Python での扱いは標準ライブラリ json で: 

import json
json.dumps({"a": 1, "b": [True, None, "hi"]})  # → '{"a": 1, "b": [true, null, "hi"]}'
json.loads('{"a": 1}')                          # → {"a": 1}  (Python の dict)

Python の True / None ↔ JSON の true / null の対応は json モジュールが自動でやってくれます。

class App(BaseHTTPRequestHandler):
    def do_GET(self):
        url = urlparse(self.path); path = url.path; q = parse_qs(url.query)
        if path == "/":              return self._text(200, "hello, http\n")
        if path == "/api/health":    return self._json(200, {"status": "ok"})
        if path == "/api/echo":      return self._json(200, {"you_said": q.get("msg", [""])[0]})
        return self._json(404, {"error": "Not Found", "path": path})

    def do_POST(self):
        path = urlparse(self.path).path
        body = self._read_json()
        if path == "/api/echo":
            return self._json(200, {"received": body})
        if path == "/api/sum":
            if "a" not in body or "b" not in body:
                return self._json(400, {"error": "a と b が必要"})
            return self._json(200, {"answer": body["a"] + body["b"]})
        return self._json(404, {"error": "Not Found"})

    def _read_json(self):
        n = int(self.headers.get("Content-Length", "0"))
        raw = self.rfile.read(n) if n else b""
        try:
            return json.loads(raw.decode("utf-8")) if raw else {}
        except json.JSONDecodeError:
            return {}

    def _text(self, status, body):
        b = body.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args): pass

📚 コラム: 「デコレータ」 ってなに?

次のステップで @route("GET", "/api/health") という見慣れない記法が出てきます。 これを使う前に、 デコレータ という概念をおさえます。 2 段階あります: Python の言語機能としてのデコレータと、 デザインパターンとしてのデコレータ。

① Python のデコレータ — 「関数を関数に変換する」 構文

Python では関数も値です。 関数を引数に取って別の関数を返す関数が書けます:

def loud(fn):
    """fn を呼び出すたびに「呼ばれた!」 と叫ぶ新しい関数を作って返す。"""
    def wrapped(*args, **kwargs):
        print(f"呼ばれた! ({fn.__name__})")
        return fn(*args, **kwargs)
    return wrapped

def hello(name):
    return f"hi, {name}"

# 1) 普通に書くと:
hello = loud(hello)      # ← hello を loud で「装飾」 して再代入
hello("alice")
# 呼ばれた! (hello)
# → 'hi, alice'

この「関数 = 関数を装飾するもの(関数)」 を毎回書くのは面倒なので、 Python は専用の構文糖衣を用意しました。 それが @: 

@loud                    # ← この一行が「hello = loud(hello)」 と等価
def hello(name):
    return f"hi, {name}"

つまり @デコレータ は 「直後の関数を、 そのデコレータに通したものに置き換える」 ためのショートカット。 関数定義の真上に書くのが約束です。

② パラメータを取るデコレータ

次のステップで使う @route("GET", "/api/health") のようにカッコ付きの デコレータは、 もう 1 段ネストします: 

def route(method, path):           # ← 引数を受け取って
    def deco(fn):                  # ← 「関数を装飾する関数」 を返す
        ROUTES[(method, path)] = fn
        return fn                  # ← 装飾と言いつつ、 中身はそのまま返す
    return deco

@route("GET", "/api/health")
def health(h):
    h._json(200, {"status": "ok"})

# これは以下と等価:
# def health(h): ...
# health = route("GET", "/api/health")(health)
#                ^^^^^^^^^^^^^^^^^^^^^^ ← deco を返す
#                                      ^^^^^^^^ ← health を deco に通して、 そのまま返す

ここで起きているのは「関数 health を、 ROUTES 辞書に登録するついでに、 中身は変えずに返す」。 次のステップで使う @route はまさにこのパターンです。

③ デザインパターンとしての「デコレータパターン」

OOP の世界のデコレータパターンは別物 (ですが似ている)。 既存のオブジェクトに新しい振る舞いを「ラップ」 して足す GoF パターンの 1 つで、 例えば「BufferedReader が FileReader をラップして読み込みバッファ機能を足す」 ような 構造を指します。

Python のデコレータ構文 (@) は関数を別の関数でラップする使い方が多く、 パターンとしてのデコレータと精神的には同じ (= 既存のものを包んで新しい振る舞いを足す)。 ただし名前が同じだけで別概念 として理解しておくと、 文脈で混同しません。

もっと知るには

  • Python 公式ドキュメント — デコレータ用語
  • functools.wraps — 装飾後の関数の __name__ や docstring を元に保つお作法
  • 典型例: Flask の @app.route(...)、 FastAPI の @app.get(...)、 Django の @login_required、 pytest の @pytest.fixture

Step 5 — リファクタ: ルーター辞書にまとめる

ハンドラが増えると do_GET / do_POST 内の if/elif の山になります。 (method, path) → handler の辞書でディスパッチする形に書き換えます。 機能は変わらないので、Step 4 のテストがそのままパスすれば成功です。

ここで初めて デコレータ (@route("GET", ...)) が登場します。 上のコラムを先に開いておくと、 これから書くコードがすんなり読めます。

    def deco(fn):

        return fn
    return deco

class App(BaseHTTPRequestHandler):
    def do_GET(self):  self._dispatch("GET")
    def do_POST(self): self._dispatch("POST")

    def _dispatch(self, method):
        path = urlparse(self.path).path
        handler = ROUTES.get((method, path))
        if handler is None:
            return self._json(404, {"error": "Not Found", "path": path,
                                    "available": [f"{m} {p}" for (m, p) in sorted(ROUTES)]})
        handler(self)

    def _read_json(self):
        n = int(self.headers.get("Content-Length", "0"))
        raw = self.rfile.read(n) if n else b""
        try:
            return json.loads(raw.decode("utf-8")) if raw else {}
        except json.JSONDecodeError:
            return {}

    def _text(self, status, body):
        b = body.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args): pass

Step 6 — 例外を JSON エラーに変える

ハンドラ内で raise bad_request("a と b は数値で") と書くだけで、 自動的に 400 + {"error": "..."} が返るようにします。 予期しない例外は traceback を出して 500。これで君のサーバが完成します。

📒 セル 1-G (= Step 1 から育てたサーバの完成版) 
import traceback

class AppError(Exception):
    def __init__(self, status, message):
        super().__init__(message)
        self.status, self.message = status, message

def bad_request(msg):  return AppError(400, msg)
def not_found(msg="Not Found"): return AppError(404, msg)

# 既存の ROUTES は引き継ぐ。 /api/sum を厳しくして例外を投げるよう書き換える。
@route("POST", "/api/sum")
def add_strict(h):
    body = h._read_json()
    if "a" not in body or "b" not in body:
        raise bad_request("a と b が必要")
    a, b = body["a"], body["b"]
    if not isinstance(a, (int, float)) or not isinstance(b, (int, float)):
        raise bad_request("a と b は数値で")
    h._json(200, {"answer": a + b})


class App(BaseHTTPRequestHandler):
    def do_GET(self):  self._dispatch("GET")
    def do_POST(self): self._dispatch("POST")

    def _dispatch(self, method):
        path = urlparse(self.path).path
        handler = ROUTES.get((method, path))
        if handler is None:
            return self._json(404, {"error": "Not Found", "path": path})
        try:
            handler(self)
        except AppError as e:
            self._json(e.status, {"error": e.message})
        except Exception as e:
            traceback.print_exc()
            self._json(500, {"error": "internal server error", "detail": str(e)})

    def _read_json(self):
        n = int(self.headers.get("Content-Length", "0"))
        raw = self.rfile.read(n) if n else b""
        try:
            return json.loads(raw.decode("utf-8")) if raw else {}
        except json.JSONDecodeError as e:
            raise bad_request(f"invalid json: {e}")

    def _text(self, status, body):
        b = body.encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(status)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args): pass
