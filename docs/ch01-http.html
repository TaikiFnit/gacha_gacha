第 1 章 — HTTPサーバーをステップで建てる

この章は 「読む」より「自分で書く」 ための章です。 6 ステップで、TCP ソケットから始めて、最終的には server/app.py と同じ作りのルーター付き HTTP サーバーを 自分の手で組み上げます。

📐 学び方 各ステップの「課題」を読んで、まず何も見ずに自分で書いてみる。 詰まったら「ヒント」を読む。それでも進まなければ「答え ( exercises/ch01/stepN_*.py) 」を見て差分を理解する。 動いたら宿題に挑戦してから次へ。

到達点 (この章を抜けるとできること)

  • HTTP リクエスト / レスポンスを「テキストの往復」として説明できる
  • http.server でメソッド + パス + JSON のサーバーを書ける
  • ルーターを辞書で管理し、例外を JSON エラーに変換できる
  • server/app.py の構造を、自分の言葉で説明できる

イントロ: HTTP は「一往復のテキスト」

クライアントが手紙を 1 通送り、サーバーが返事を 1 通返す。 手紙の中身はただのテキスト。 

POST /api/login HTTP/1.1
Host: localhost:8000
Content-Type: application/json
Content-Length: 39

{"name":"alice","password":"secret"}
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Length: 24

{"user":{"id":1,"name":"alice"}}

この上に何を載せても HTTP。GET も POST も WebSocket の握手も、ぜんぶ 最初はこのテキストです。これを素手で書いて返すのが Step 1。

Step 1 — TCPだけで HTTP風のテキストを返す

🎯 課題

socket モジュールだけで、127.0.0.1:9000 で 待ち受けるサーバーを書く。curl で接続したら "hello, raw tcp\n" を返して、ターミナルに 受信したリクエストの全文を表示する。

💡 ヒント

  • socket.socket(AF_INET, SOCK_STREAM) → bind → listen → accept
  • 受信は conn.recv(4096)。bytes が返る
  • 応答は HTTP/1.1 200 OK\r\n から始める。 ヘッダの後ろは空行 (\r\n\r\n) を必ず入れる
  • Content-Length はバイト数。これが嘘だと受信側が固まる

🧪 動作確認

python exercises/ch01/step1_socket.py
# 別ターミナル:
curl -v http://127.0.0.1:9000/

curl の出力に > GET / HTTP/1.1 など送信ヘッダ、 < HTTP/1.1 200 OK など応答ヘッダが見えればOK。

Step 2 — http.server に乗り換えて Hello GET

🎯 課題

Step 1 では「ヘッダを書いて、空行入れて、本文書いて」を全部手でやった。 毎回それは辛いので、Python 標準の http.server に乗り換える。 BaseHTTPRequestHandler をサブクラス化し、 do_GET をオーバーライドして "hello, http\n" を返す最小サーバーを書く。

💡 ヒント

  • 呼び出し順は send_response → send_header (複数可) → end_headers → wfile.write を必ず守る
  • HTTPServer((host, port), HandlerClass).serve_forever() で起動
  • self.wfile.write(...) は bytes を要求する

Step 3 — パスで分岐 + クエリ受け取り

🎯 課題

メソッドパス応答
GET/text/plain で hello
GET/api/health{"status":"ok"}
GET/api/echo?msg=X{"you_said":"X"}
GETその他404 + {"error":"Not Found","path":...}

💡 ヒント

  • パスとクエリを分けるには urllib.parse.urlparse(self.path)
  • クエリの解析は urllib.parse.parse_qs(...) → 値はリストで返るので q.get("msg", [""])[0] のように取り出す
  • JSON 応答は json.dumps({...}, ensure_ascii=False).encode("utf-8")

curl http://127.0.0.1:8001/api/health
curl 'http://127.0.0.1:8001/api/echo?msg=hi%20there'

Step 4 — POSTでJSONを受け取る

🎯 課題

メソッドパス本文応答
POST/api/echo任意のJSON {"received":...,"size":N}
POST/api/sum{"a":n,"b":m} {"answer":n+m}

JSON が壊れていたら 400 を返す。/api/sum で a か b が無ければ 400。

💡 ヒント

  • 本文の長さは self.headers.get("Content-Length", "0")
  • 本文は self.rfile.read(n) で bytes として読む
  • json.JSONDecodeError を try/except で拾う

Step 5 — ルーター辞書でデータ駆動に

🎯 課題

do_GET / do_POST 内の if/elif の山をやめて、 ROUTES = {(method, path): handler} という辞書でディスパッチする。 ハンドラの登録は @route("GET", "/api/health") のように書ける デコレータで。

💡 ヒント

ROUTES = {}

def route(method, path):
    def deco(fn):
        ROUTES[(method.upper(), path)] = fn
        return fn
    return deco

@route("GET", "/api/health")
def health(h):
    h._json(200, {"status": "ok"})

class App(BaseHTTPRequestHandler):
    def do_GET(self):  self._dispatch("GET")
    def do_POST(self): self._dispatch("POST")
    def _dispatch(self, method):
        handler = ROUTES.get((method, urlparse(self.path).path))

Step 6 — 例外をJSONエラーに変換する

🎯 課題

ハンドラ内で raise bad_request("a と b は数値で") と書くと、 自動的に 400 + {"error": "..."} が返る形を作る。 予期しない例外は traceback を stderr に出して 500 を返す。

💡 ヒント

class AppError(Exception):
    def __init__(self, status, message):
        super().__init__(message)
        self.status, self.message = status, message

def bad_request(msg):  return AppError(400, msg)
def not_found(msg="Not Found"): return AppError(404, msg)

# _dispatch 内:
try:
    handler(self)
except AppError as e:
    self._json(e.status, {"error": e.message})
except Exception as e:
    traceback.print_exc()
    self._json(500, {"error": "internal server error", "detail": str(e)})
