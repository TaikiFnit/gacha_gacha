第 5 章 — ガチャ抽選を本実装する

Ch.4 末で「フロント全機能が表面上は動く」 状態にしました。 でも引いても必ずドラゴン、 コインは固定。 この章でいよいよこのシステムの本丸 — 重み付き乱択でキャラを引いて、 コインを消費して、 履歴を DB に残す — を本実装します。 ユーザー管理 (パスワード / 認証) は次の章までお預け、 今は「guest さん 1 人がガチャを楽しむ」 状態をひたすら作り込みます。

5 ステップで:

  1. 必要なテーブル + guest ユーザーを作る
  2. /api/me を実 DB から読むように
  3. /api/gacha/list を実 DB SELECT に
  4. 重み付き乱択 (draw 関数) を書いて、 シミュレーションで確かめる
  5. /api/gacha/pull を本実装 (transaction でくくる)

ステップ 0 — テーブルと guest ユーザーを揃える

Ch.2 で users を作っていますが、 ガチャに必要な情報が足りません。 また、 キャラ / ガチャ筐体 / 排出設定 / 所持履歴 の 4 テーブルも必要です。 ここで一気に揃えます。

📒 セル 5-A — users.coins 列を追加 + guest ユーザー 
%%sql
ALTER TABLE users ADD COLUMN coins INTEGER NOT NULL DEFAULT 1000;

INSERT INTO users (id, name, pass_hash, display_name, coins)
VALUES (1, 'guest', '', 'ゲスト', 1000)
ON CONFLICT DO NOTHING;

SELECT * FROM users;
📚 コラム: ALTER TABLE と ON CONFLICT DO NOTHING

ALTER TABLE: 既存テーブルの定義を変える SQL。 列を追加 / 削除 / 型変更 などに使う。 本番運用では「データを壊さずスキーマだけ変える」 のが鉄則で、 列追加は安全だが型変更や削除は要注意。

ON CONFLICT DO NOTHING: SQLite/Postgres の便利機能。 UNIQUE 制約や PRIMARY KEY と衝突する INSERT があったとき、 エラーにせずに「何もしない」 で終わる。 スクリプトを何度実行しても結果が変わらない (= 冪等性) を作るのに使う。

📚 コラム: 「外部キー (Foreign Key)」 と REFERENCES

gacha_items.gacha_id INTEGER NOT NULL REFERENCES gachas(id) — この REFERENCES が外部キー (Foreign Key, FK) の指定です。 「gacha_id 列に入る値は、 gachas テーブルに存在する id でなければならない」 という制約。

例えば INSERT INTO gacha_items (gacha_id, ...) VALUES (999, ...) をやろうとすると、 gachas に id=999 が無いので DB が弾く (FK 違反)。 これで「孤立した排出設定」 のような壊れたデータの混入を防げる。

ON DELETE CASCADE = 親 (例: users) を消したら子 (user_characters) も連鎖して消える、 という挙動。 「あるユーザーを完全削除」 の意味が自然になる。

ステップ 1 — /api/me を実 DB から

Ch.4 末で /api/me はハードコードで guest を返していました。 これを実 DB の guest 行 を読むように差し替えます。 これでガチャ画面に表示される「所持コイン」 が、 ガチャを引くたびに DB と同期するようになります。

📒 セル 5-D — sqlite 接続 (再掲) + 動作確認 
import sqlite3
from contextlib import contextmanager

DB_PATH = "gacha.db"

@contextmanager
def get_conn():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()

with get_conn() as conn:
    cur = conn.execute("SELECT id, name, coins FROM users WHERE id = 1")
    print("guest:", dict(cur.fetchone()))
📒 セル 5-E — /api/me を実 DB に 
@route("GET", "/api/me")
def me(h):
    # まだユーザー認証は無い。 全員 guest (id=1) として扱う。
    # Ch.7 で「ログインしているユーザー」 を引くように差し替える。
    with get_conn() as conn:
        cur = conn.execute(
            "SELECT id, name, display_name, coins FROM users WHERE id = 1"
        )
        row = cur.fetchone()
    h._json(200, {"user": dict(row)})

print("✅ /api/me が実 DB の guest を返すように")
📚 コラム: SQL インジェクション と ? プレースホルダ

SQL に値を埋め込むとき、 文字列連結で書くと攻撃者にテーブルを破壊されかねません。 例えば: 

# ❌ 絶対やってはいけない書き方
name = body.get("name")
cur = conn.execute(f"SELECT * FROM users WHERE name = '{name}'")

ここで name = "'; DROP TABLE users; --" が来ると、 結果として実行される SQL は: 

SELECT * FROM users WHERE name = '';
DROP TABLE users;
--'

users テーブルが丸ごと消える。 これが SQL インジェクション。

プレースホルダ (?) を使うと、 ライブラリが値を「データ」 として安全に扱ってくれる: 

# ✅ 安全な書き方
cur = conn.execute("SELECT * FROM users WHERE name = ?", (name,))

変数を SQL に埋めるときは必ず ?。 例外なし。 (Postgres / psycopg では %s という別の記号を使うが、 役割は同じ — Ch.8 で扱う)

ステップ 2 — /api/gacha/list を実 DB から

ガチャ筐体一覧は gachas テーブルから取ってくる。 ついでに「排出キャラ数」 と「weight 合計」 も 集計で添える。

📒 セル 5-F — gacha_list を本物に 
@route("GET", "/api/gacha/list")
def gacha_list(h):
    with get_conn() as conn:
        rows = conn.execute("""
            SELECT g.id, g.name, g.price,
                   COUNT(gi.id)               AS pool_size,
                   COALESCE(SUM(gi.weight), 0) AS total_weight
              FROM gachas g
              LEFT JOIN gacha_items gi ON gi.gacha_id = g.id
             GROUP BY g.id
             ORDER BY g.id
        """).fetchall()
    h._json(200, {"gachas": [dict(r) for r in rows]})

print("✅ /api/gacha/list が実 DB から返すように")

JOIN、 GROUP BY、 COUNT/SUM という新しい SQL の道具が一気に出てきましたが、 ここでは「ガチャごとに排出設定の数と重み合計を集計する」 と思えば OK。 仕組みは次章 (Box) でじっくりやります。

ステップ 3 — 重み付き乱択 (draw 関数)

ガチャの肝は「キャラごとに違う出やすさ」。 これを「乱数 + weight」 で実装します。 アルゴリズムは古典的:

  1. weight の合計を分母にして、 0〜合計 の一様乱数 r を 1 つ引く
  2. 各キャラの weight を順に足していき、 累積が r を超えた時点のキャラが当選
📚 コラム: 一様乱数と random.choices

一様乱数 = 与えた範囲のどの値も等しい確率で選ばれる乱数。 Python の random.uniform(0, 1) や random.random() がこれ。

Python 標準の random.choices(items, weights=[...], k=1) は、 上の累積和+一様乱数の アルゴリズムをそのまま実装してくれます。 自分で書く必要はないが、 仕組みは理解しておくと便利。

本物のサービスでは、 抽選結果をプレイヤーが予測できないように random.SystemRandom (= OS の暗号学的乱数源を使う) を採用するのが推奨。 本教材もそうしている。

📒 セル 5-G — draw 関数 + シミュレーション 
import random
from dataclasses import dataclass

@dataclass
class GachaItem:
    character_id: int
    name: str
    rarity: int
    emoji: str
    weight: int

def fetch_pool(conn, gacha_id):
    """指定ガチャの排出プールを取ってくる。"""
    rows = conn.execute("""
        SELECT c.id AS character_id, c.name, c.rarity, c.emoji, gi.weight
          FROM gacha_items gi
          JOIN characters c ON c.id = gi.character_id
         WHERE gi.gacha_id = ?
         ORDER BY c.rarity, c.id
    """, (gacha_id,)).fetchall()
    return [GachaItem(**dict(r)) for r in rows]

def draw(pool, rng=None):
    """重み付き乱択を 1 回行う。"""
    if not pool:
        raise ValueError("空のプール")
    rng = rng or random.SystemRandom()
    weights = [item.weight for item in pool]
    return rng.choices(pool, weights=weights, k=1)[0]


# シミュレーションで分布を確かめる
from collections import Counter
with get_conn() as conn:
    pool = fetch_pool(conn, 1)
total_w = sum(p.weight for p in pool)
counts = Counter()
N = 100_000
rng = random.Random(42)         # 再現可能性のため seed 固定
for _ in range(N):
    counts[draw(pool, rng=rng).name] += 1

print("通常ガチャ 10万回シミュレーション:")
for p in sorted(pool, key=lambda x: -x.weight):
    expected = p.weight / total_w * 100
    actual   = counts[p.name] / N * 100
    print(f"  {p.name:14s} 期待 {expected:5.2f}%  実測 {actual:5.2f}%")

ステップ 4 — /api/gacha/pull を本実装

ガチャを 1 回引く処理に必要なステップ:

  1. guest (= user_id=1) のコイン残高を確認
  2. 抽選
  3. コインを減らす (UPDATE)
  4. 履歴に追加 (INSERT)
  5. 返事を返す

ステップ 3 と 4 は必ず両方一緒に成功するか、 両方失敗でなければなりません。 もし 3 だけ成功して 4 が失敗 (例: 急なネットワーク断) すれば、 「コインだけ減ってキャラもらえない」 という大事故になります。 これを防ぐ仕掛けがトランザクション。 詳しくは下のコラム。

📚 コラム: トランザクションって?

トランザクション = 複数の DB 操作を「まとめて 1 セット」 として扱う仕組み。 セットの中身は全成功 or 全失敗 しかない。

SQL で書くと:

BEGIN;
   UPDATE users SET coins = coins - 100 WHERE id = 1;
   INSERT INTO user_characters (user_id, character_id) VALUES (1, 5);
COMMIT;

BEGIN から COMMIT までが 1 つのトランザクション。 途中で何か失敗したら ROLLBACK で全てを「無かったこと」 にできる。

本教材の get_conn() ヘルパは、 with ブロックを抜けるときに自動 COMMIT、 例外で自動 ROLLBACK する仕掛けが入っています。 だから with get_conn() as conn: ブロック全体が 1 つのトランザクションになる。

DB の世界では ACID という用語があり、 トランザクションが提供する 4 性質の頭文字:

  • Atomicity (原子性) — 全成功か全失敗
  • Consistency (整合性) — 制約は常に守られる
  • Isolation (独立性) — 同時実行しても他のトランザクションに干渉しない
  • Durability (永続性) — COMMIT したら停電しても消えない

Ch.5 で必要なのは主に A (原子性)。 残り 3 つは別の場面 (並行アクセス、 障害耐性) で効いてくる。

📒 セル 5-H — /api/gacha/pull の本実装 
@route("POST", "/api/gacha/pull")
def gacha_pull(h):
    body = h._read_json()
    gacha_id = body.get("gacha_id")
    if not isinstance(gacha_id, int):
        raise bad_request("gacha_id は整数で")

    user_id = 1   # まだ認証無し。 全員 guest として扱う

    # with ブロック全体が 1 つのトランザクション。
    # 中で例外が起きれば自動 ROLLBACK で DB は手付かずの状態に戻る。
    with get_conn() as conn:
        # ガチャ情報
        g = conn.execute(
            "SELECT id, name, price FROM gachas WHERE id = ?",
            (gacha_id,)
        ).fetchone()
        if g is None:
            raise not_found("そのガチャは存在しません")

        # コイン残高チェック
        coins_now = conn.execute(
            "SELECT coins FROM users WHERE id = ?", (user_id,)
        ).fetchone()["coins"]
        if coins_now < g["price"]:
            raise bad_request(f"コインが足りません (必要 {g['price']} / 所持 {coins_now})")

        # プール取得 + 抽選 (DB に書き込む前にやる)
        pool = fetch_pool(conn, gacha_id)
        if not pool:
            raise bad_request("そのガチャに排出設定がありません")
        won = draw(pool)

        # ★ ここから 2 つの書き換え (UPDATE + INSERT) を 1 セットとしてやる
        new_coins = conn.execute(
            "UPDATE users SET coins = coins - ? WHERE id = ? RETURNING coins",
            (g["price"], user_id),
        ).fetchone()["coins"]

        obtained_at = conn.execute(
            "INSERT INTO user_characters (user_id, character_id) VALUES (?, ?) "
            "RETURNING obtained_at",
            (user_id, won.character_id),
        ).fetchone()["obtained_at"]

    h._json(200, {
        "gacha":     {"id": g["id"], "name": g["name"], "price": g["price"]},
        "character": {"id": won.character_id, "name": won.name,
                      "rarity": won.rarity, "emoji": won.emoji},
        "obtained_at": obtained_at,
        "coins": new_coins,
    })

print("✅ /api/gacha/pull が本実装に")

  2. ガチャ画面で「引く」 ボタンを押す → ランダムなキャラが出る (ドラゴン以外も!)
  3. 所持コインが 1000 → 900 → 800 ... と本当に減っていく
  4. 10 回引くとコインが 0 に → 「コインが足りません」 のエラー
