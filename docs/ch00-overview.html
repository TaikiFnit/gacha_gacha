第 0 章 — 全体像と学び方

最初に、この教材で何をやるのか、なぜやるのか、どう進めるのか、という 地図 を渡しておきます。地図がなければ、いきなり川に流されている 気分になりやすいので。

0.1 なぜガチャシステムなのか

バックエンドとデータベースの教材は世の中にたくさんあります。 が、典型的な「メモアプリを作る」「ブログを作る」だと、 テーブルが 1〜2 個で済んでしまい、リレーション (関係) を扱う面白さ が出てきません。ガチャは違います。

  • ユーザーがいる (= 認証・所有という概念)
  • キャラがいる (= マスタデータ)
  • ガチャ筐体がいる (= マスタの組み合わせ)
  • 排出設定がある (= 多対多 + 重み)
  • ユーザー所持がある (= 多対多 + 履歴)

「複数のテーブルを正しく組み合わせて答えを返す」 という、データベースの本領が試される題材です。しかも、 重み付き乱択や集計など、ロジックも一癖あります。

0.2 何を作るのか

ブラウザで動く、ものすごく素朴なガチャゲームです。 ログインして、コインを払ってガチャを引き、結果が Box に積まれていく。 これを フレームワークなし で実装します。 具体的にはこの 3 つだけ:

  • Python 標準ライブラリ http.server (HTTP サーバー)
  • psycopg (PostgreSQL ドライバ。これは外部だけど、生 SQL を書く用途なので軽量)
  • 素の HTML/CSS/JS (フロント)
📝 補足 実務では Django / FastAPI / Spring Boot のようなフレームワークを使います。 でも、いきなりフレームワークから入ると「何が魔法で、何がプロトコルの規定なのか」 が混ざってわからなくなります。素手で 1 度組んでおく と、フレームワークが何を肩代わりしているかが透けて見えるようになります。

0.5 学習の流儀 (これが一番大事かもしれない)

AI が一瞬で全部書ける今、それでも自分の手で書く意味があります。 この教材を進めるときは、章ごとに次のループを回してください:

  1. 章を最後まで読む。流れだけつかむ
  2. 該当ファイル (例: server/app.py) を実際に開いて読む
  3. 動かす。サーバー起動して curl やブラウザで叩く
  4. 壊す。わざと SQL を間違える、ステータスを変える、 パスワードチェックを外す。何が起きるか見る
  5. 直す。直しながら、なぜそれで動くのかを言語化する
🛠 やってみる 第 1 章に入る前に、まずローカルでサーバーが起動できるか確認しておくと スムーズです。プロジェクト直下で: 
docker compose up -d
python -m venv .venv && source .venv/bin/activate
pip install -r server/requirements.txt
python -m server.app

「listening on http://localhost:8000」と出たら準備完了。

0.6 困ったとき

  • DB が起動しない → docker compose logs db でログを確認
  • Python が import できない → 仮想環境がアクティブか確認 (which python)
  • ブラウザでログインできない → 開発者ツール「Network」タブで API のステータスを見る
  • 「もう全部わからない」→ 章を 1 つ戻す。 下の層の理解が足りていないことが多いです
