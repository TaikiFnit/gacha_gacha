Chapter 0 所要時間: 60〜90 分 動かすもの: 自分の Windows PC (Python + Docker Desktop + Bruno)

第 0 章 — 全体像と環境構築

この教材は自分の手元の Windows PC でバックエンドを組み立てる形式で進みます。 まずは、 何を作るのか、 どう進めるのか、 そして道具を揃えるところまでを片付けます。 0 章だけは少し時間がかかりますが、 ここを通過してしまえば、 1 章以降はずっと 「コードを書く → 動かす → 試す」 のサイクルだけで進めます。

0.1 なぜガチャシステムなのか

バックエンドとデータベースの教材は世の中にたくさんあります。 が、典型的な「メモアプリを作る」「ブログを作る」だと、 テーブルが 1〜2 個で済んでしまい、リレーション (関係) を扱う面白さ が出てきません。 ガチャは違います。

  • ユーザーがいる (= 認証・所有という概念)
  • キャラがいる (= マスタデータ)
  • ガチャ筐体がいる (= マスタの組み合わせ)
  • 排出設定がある (= 多対多 + 重み)
  • ユーザー所持がある (= 多対多 + 履歴)

「複数のテーブルを正しく組み合わせて答えを返す」 という、 データベースの本領が試される題材です。 しかも、 重み付き乱択や集計など、 ロジックも一癖あります。

0.2 まず Web の世界の登場人物を整理

本教材を読むのに最低限必要な用語を、 ここで一気にざっくり押さえます。 初耳でも構いません。 各章で実際に動かしながら何度も出てくるので、 最初は「ふーん」 で OK。

用語意味 (簡略)例
クライアント サービスを利用する側。 「お客さん」 Web ブラウザ、 スマホアプリ、 REST クライアント
サーバ サービスを提供する側。 「お店」。 24時間動いてリクエストを待つ Google のサーバ、 ガチャゲームのサーバ
フロントエンド ユーザーが直接触る側 (= クライアントの中身) ブラウザで動く HTML/CSS/JS
バックエンド 裏で動くサーバ側のロジック Python サーバ + DB
HTTP クライアントとサーバが「テキストで会話する」 ためのルール (= プロトコル) Ch.1 で詳しくやる
API 「サーバにこう聞いたら、 こう答えてくれる」 という決まり事の窓口 GET /api/users でユーザー一覧を返す、 等
REST API HTTP で上記の API を提供する、 業界で広く使われるスタイル。 URL でリソースを表し、 GET/POST/PUT/DELETE でその操作を表す 本教材で作る API はぜんぶ REST スタイル
JSON データをテキストで表す形式。 REST API の応答で最頻出 {"name": "alice", "age": 22}
データベース (DB) データを永続的に保存する仕組み Ch.2 で詳しくやる
Docker 「アプリと、 アプリが動くために必要なもの一式」 を箱詰めにして、 同じように動かせる仕組み 本教材では PostgreSQL を Docker で起動する

本教材では バックエンド (= ガチャの API サーバ + DB) を自分で手を動かして作り、 フロントエンド (= ガチャ画面) は既製品を後から繋げます。 Web 開発の中心にあるのが「クライアント ⇄ HTTP ⇄ サーバ ⇄ DB」 の往復、 と覚えておけば道に迷いません。

0.3 何を作るのか

ブラウザで動く、 ものすごく素朴なガチャゲームです。 ログインして、 コインを払ってガチャを引き、 結果が Box に積まれていく。 これを フレームワークなし で実装します。 具体的にはこの 3 つだけ:

  • Python 標準ライブラリ http.server (HTTP サーバー)
  • PostgreSQL (Docker コンテナ) + psycopg (Python から DB を叩くライブラリ)
  • 素の HTML/CSS/JS (フロント。 既製品を提供します)
📝 補足 実務では Django / FastAPI / Spring Boot のようなフレームワークを使います。 でも、 いきなりフレームワークから入ると「何が魔法で、 何がプロトコルの規定なのか」 が混ざってわからなくなります。素手で 1 度組んでおく と、 フレームワークが何を肩代わりしているかが透けて見えるようになります。

0.6 学習の流儀 — 段階で組み立てる

AI が一瞬で全部書ける今、 それでも自分の手で書く意味は何か。 この教材では、 1 章で書いた小さなコードを、 次の章でそのまま書き足し / 書き換えて拡張していく 形を採用しています。 写経や丸ごとコピペではなく、 「前に自分が書いたコード」 を起点に 機能を 1 つずつ足していくので、 出来上がったときに 「自分で組み立てた」 感覚が残ります。

章ごとに、 次の流れを繰り返します:

  1. 動かす — 各ステップのコードをエディタにコピペして保存 → ターミナルで実行
  2. 確認する — 期待される出力と一致するか見る
  3. 壊す — 1 か所だけ書き換えて、 出力がどう変わるか見る (= 仕組みの理解確認)
  4. 拡張する — 次のステップで前のコードに機能を 1 つ足す。 前にできていたことは引き続き動くか確認

一気に全部書いて最後にまとめてテスト、 ではなく、 動く → 壊して試す → 拡張する を小さい単位で何度も繰り返します。 最終的に出来上がるコードは、 リポジトリの完成版 (server/ / db/) と ほぼ同じ形に到達します。

迷ったり詰まったりしたときは、 リポジトリ直下の完成版コードを 「同じ道を最後まで歩いた人の足跡」 として参照してください。 あなたのコードを否定する正解ではなく、 進む方向を示す地図として役立ちます。

0.7 環境構築 — Windows ローカル前提

ここからは実際に手を動かします。 必要な道具は 4 つだけ:

  1. Python 3.11 以降 — 教材本体を書く言語
  2. Docker Desktop — Ch.2 から PostgreSQL を起動するのに使う
  3. Bruno — REST API を叩いて応答を確認するクライアント (Ch.1 から)
  4. VS Code (任意だが強く推奨) — エディタ

順に入れていきます。 すべて個人利用なら無料です。

0.7.1 Python をインストール

python.org の Windows 版ダウンロードページ から、 最新の安定版 (本教材執筆時点では 3.12 系) の「Windows installer (64-bit)」 を ダウンロードしてください。

⚠️ 必ずチェック: 「Add python.exe to PATH」 インストーラの最初の画面で、 一番下にある 「Add python.exe to PATH」 のチェックボックスを 必ずオンにしてから「Install Now」 を押してください。 これを忘れると、 PowerShell から python コマンドが直接打てなくなり、 後で全部の手順がうまくいきません。 もし忘れた場合は、 一度アンインストールしてやり直すのが楽です。

0.7.2 PowerShell で Python が動くか確認

Windows のスタートメニューから「PowerShell」 を起動してください (「Windows PowerShell」 でも 「PowerShell 7」 でもどちらでも OK)。 下のコマンドを 1 つずつ打ってみます。

📒 確認 1 — Python のバージョンを見る 
# Python のバージョンを表示
python --version

# どこにインストールされたか表示
python -c "import sys; print(sys.executable)"
✅ 期待される出力 (バージョン番号は環境による) 
Python 3.12.3
C:\Users\<あなたの名前>\AppData\Local\Programs\Python\Python312\python.exe

もし python : 用語 'python' は、 ... のようなエラーが出たら、 PATH 設定を忘れています。 0.7.1 の警告に戻ってインストールし直してください。

📚 コラム: python と py の違い

Windows には py という Python ランチャーが標準で入る場合があります。 本教材では一貫して python を使います。 もし環境によって python が動かず py なら動く場合は、 すべての python を py に読み替えてください。

0.7.3 ターミナルで Python をちょっと触ってみる

環境変数 PATH を通したかどうかは、 上の python --version で確かめました。 せっかくなので、 数行だけ対話モードで動かしてみます。

📒 確認 2 — 対話モードで Python に話しかける 
# Python の対話モード (REPL) に入る
python

# 以下、 >>> プロンプトで入力していく
>>> 1 + 1
2
>>> "hello, " + "Python"
'hello, Python'
>>> for i in range(3):
...     print(i, "ガチャ")
...
0 ガチャ
1 ガチャ
2 ガチャ
>>> exit()

>>> が出ているときは Python が「次の命令を待っている」 状態です。 exit() で抜けて PowerShell に戻ります。

📝 ループは 4 スペース字下げ for i in range(3): の次の行は必ず 4 スペース下げてから print を打ってください。 Python では字下げで「ブロック」 を表現します (Java の { } や C 系の波括弧の代わり)。 対話モードでは、 字下げが必要な行は ... プロンプトに変わります。 ブロックを終わるには空行で Enter を押します。

0.7.4 作業用フォルダを作る + Python ファイルを動かす

ガチャ教材で書くコードを置く場所を作ります。 PowerShell で実行してください。

📒 確認 3 — 作業フォルダを作って移動 
# ホームディレクトリ (= C:\Users\<あなたの名前>) の下に gacha_workspace を作る
mkdir $HOME\gacha_workspace
cd    $HOME\gacha_workspace

# 今いる場所を表示
pwd

# このフォルダの中身 (空のはず)
ls

次に、 簡単な Python スクリプトをファイルとして書いて、 ファイル経由で実行してみます。 対話モードと違って、 ファイルに書いたコードは何度でも再実行できます。

📒 確認 4 — hello.py を作って動かす 
# hello.py を作る (PowerShell の 'Set-Content' でファイル作成)
@"
# hello.py
print('Hello, Python!')
print(2 ** 10, '回ガチャを引いた気分')
"@ | Set-Content -Encoding utf8 hello.py

# 実行
python hello.py
✅ 期待される出力 
Hello, Python!
1024 回ガチャを引いた気分

上の @"..."@ はヒアドキュメント記法で、 PowerShell で複数行を 1 ファイルにまとめて 書き出すときに便利です。 普段は VS Code などのエディタで hello.py を開いて編集します (後述)。

0.7.5 VS Code を入れる (任意だが強く推奨)

VS Code 公式 から Windows 版をダウンロード → インストール。 推奨拡張は次の 2 つだけ:

  • Python (Microsoft 公式) — 構文ハイライト、 補完、 デバッグ
  • SQLTools + SQLTools PostgreSQL/Cockroach Driver — Ch.2 で DB を覗くのに便利 (DBeaver や pgAdmin が好みなら不要)

VS Code の右下に表示される改行コードは LF に統一しておくのがおすすめです (リポジトリ直下の .gitattributes で自動的にそうなりますが、 既存ファイルを 開いて見るときの安心材料)。

0.7.6 Docker Desktop を入れる

Ch.2 から PostgreSQL を Docker コンテナで起動します。 Docker Desktop 公式 から Windows 版 (AMD64 もしくは ARM64) をダウンロードしてインストールしてください。

⚠️ Docker Desktop の前提
  • Windows 10 以降 (Pro / Home どちらでも OK)
  • WSL 2 が有効になっていること (インストーラが自動でセットアップを促してくれます。 「Use the WSL 2 based engine」 がデフォルト)
  • 会社 PC で管理者権限が必要な操作が起きるので、 自由にインストールできない環境では事前に IT 部門と相談してください

インストールが終わったら、 一度 PC を再起動してから Docker Desktop を起動します。 タスクトレイに クジラのアイコンが出て、 「Engine running」 と表示されれば準備完了。

📒 確認 5 — PowerShell から docker が見えるか 
# Docker のバージョン
docker --version
docker compose version

# 動いているコンテナ一覧 (まだ何もないので空)
docker ps
✅ 期待される出力 (バージョンは環境による) 
Docker version 27.3.1, build ce12230
Docker Compose version v2.30.3-desktop.1
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

もし docker : 用語 'docker' は ... となれば、 Docker Desktop がまだ起動していない、 または PowerShell を Docker Desktop インストール前に開いたセッションのままです。 PowerShell を一度閉じて 開き直してください。

0.7.7 Bruno (REST クライアント) を入れる

Ch.1 で HTTP サーバを動かしたら、 ブラウザの URL バー以外からも叩いてみたくなります。 そのときに使う API クライアントが Bruno です。 軽量、 オープンソース、 アカウント不要、 設定ファイルがプレーンテキストで git に commit できる、 と教材に向いています。

Bruno 公式 から Windows 版を ダウンロード → インストール。 起動して空のウィンドウが開けば OK です。 使い方は Ch.1 で扱います。

📚 コラム: なぜ curl ではなく Bruno?

本教材でも curl はよく使います。 ただ、 ヘッダや body を組み立てたり、 何度も呼び直したり、 request を保存しておきたい場面では GUI クライアントの方が圧倒的に楽です。 Bruno を選んでいるのは:

  • OSS でアカウント登録不要 (Postman は無料でもアカウント要)
  • request 定義が .bru というプレーンテキストファイル なので、 学習プロジェクトを git に commit してそのまま共有できる
  • 動作が軽い

Postman / Hoppscotch デスクトップ / VS Code の REST Client 拡張など、 既に使い慣れたものがあれば それで構いません。 本教材の手順では Bruno を前提に書いてあるだけです。

0.7.8 Git (任意) — 完成版コードを答え合わせに使うなら

この教材のリポジトリ gacha_gacha をローカルに clone しておくと、 自分で組み立てた途中で「完成版はどう書いているのか」 を簡単に比べられて便利です。 Git for Windows をインストールしてから:

📒 確認 6 — 教材リポジトリを clone 
cd $HOME
git clone https://github.com/taikifnit/gacha_gacha.git
cd gacha_gacha
ls

作業用の $HOME\gacha_workspace とは別に $HOME\gacha_gacha ができます。 自分のコードは gacha_workspace、 教材ソースは gacha_gacha、 と分けて使います。

0.8 困ったとき

  • 「python が認識されない」 → PATH 設定を忘れている。 0.7.1 の警告参照。 アンインストール → 再インストールが早い
  • 「docker が認識されない」 → Docker Desktop を起動した状態で、 PowerShell を開き直す。 起動中なのにダメなら一度 PC を再起動
  • 「Address already in use」 (ポート 8000 / 5432 などが使われている) → Get-NetTCPConnection -LocalPort 8000 で何が掴んでいるか確認。 不要なプロセスは Stop-Process -Id <PID> で止める
  • PowerShell でスクリプトを実行できない (「実行ポリシー」 エラー) → Set-ExecutionPolicy -Scope CurrentUser RemoteSigned を 1 度実行
  • 「もう全部わからない」 → 章を 1 つ戻す。 下の層の理解が足りていないことが多いです
💡 ここまでで不安があれば
  • python --version でバージョン番号が出る
  • docker ps で表が表示される (中身は空 OK)
  • Bruno が起動して、 ウィンドウが開く

この 3 つが揃ったら、 第 1 章へ進む準備は万全です。
