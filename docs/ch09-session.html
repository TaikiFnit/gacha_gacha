Ch.1〜8 で「動くガチャシステム」 が手元の Colab で完成しました。 ここで Colab を卒業し、 本番想定の環境 (PostgreSQL + Docker + 分割されたファイル + 自動テスト) に ステップアップします。

9.1 Colab を卒業 — Notebook を持ち帰る

Colab メニュー 「ファイル」 → 「ダウンロード」 → 「.ipynb をダウンロード」 で全セルが手元に落ちてきます。 ここから必要なコードを .py ファイルにコピーします。

ローカルに作業フォルダを作る:

mkdir -p ~/gacha_gacha/{db,server,web,tests}
cd ~/gacha_gacha

web/ は Ch.4 で既にダウンロード済みのフロント 3 ファイル (index.html / app.js / style.css) を移動。

Python 仮想環境を作る

python -m venv .venv
source .venv/bin/activate          # Windows は .venv\Scripts\activate
python -m pip install --upgrade pip
📚 コラム: 仮想環境って?

Python はプロジェクトごとに独立したパッケージセットを持つのが定番。 python -m venv .venv でこのプロジェクト専用の Python 環境ができ、 source .venv/bin/activate で「以後の pip install はそこに入れてね」 と OS に伝える。

これをやらないと、 pip install がシステム全体の Python に影響して、 別プロジェクトとバージョン衝突したりする。 1 プロジェクト = 1 仮想環境 がお作法。

9.2 Postgres を Docker で起動

ローカル PC に直接 Postgres をインストールするのも可能ですが、 OS による手順差を避けて Docker コンテナとして動かすのが今風。 「壊れたら docker compose down -v で全て無かったことにできる」 のが大きな利点。

📚 コラム: Docker / コンテナとは

コンテナ = OS とアプリと依存ライブラリをひとまとめにした「ポータブルな箱」。 サーバ (= Postgres、 Nginx、 etc) を「箱」 として配布できるので、 「俺のマシンでは動くんだけど」 問題が消える。

Docker Compose = 複数のコンテナの起動設定を 1 つの YAML ファイルにまとめるツール。 docker compose up -d 1 行でガチャ用 Postgres が起動する。

本教材では Postgres を Docker で動かしますが、 アプリ自体 (Python サーバ、 フロント) は ローカルで素のまま動かします。 「インストールが面倒な部分だけ Docker に任せる」 という良いとこ取り。

docker-compose.yml を置く

schema.sql / seed.sql を Postgres 方言で書く

Ch.2/Ch.6/Ch.7 で sqlite で作ったテーブル定義を、 Postgres 方言で書き直します。 違いは小さい: INTEGER PRIMARY KEY AUTOINCREMENT → BIGSERIAL PRIMARY KEY、 TEXT DEFAULT (datetime('now')) → TIMESTAMPTZ DEFAULT NOW() など。

📄 ~/gacha_gacha/db/schema.sql 
CREATE TABLE users (
    id           BIGSERIAL    PRIMARY KEY,
    name         TEXT         NOT NULL UNIQUE,
    pass_hash    TEXT         NOT NULL,
    display_name TEXT         NOT NULL,
    coins        INTEGER      NOT NULL DEFAULT 1000 CHECK (coins >= 0),
    created_at   TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE TABLE characters (
    id     BIGSERIAL PRIMARY KEY,
    name   TEXT      NOT NULL UNIQUE,
    rarity SMALLINT  NOT NULL CHECK (rarity BETWEEN 1 AND 5),
    emoji  TEXT      NOT NULL DEFAULT '❓'
);

CREATE TABLE gachas (
    id    BIGSERIAL PRIMARY KEY,
    name  TEXT      NOT NULL UNIQUE,
    price INTEGER   NOT NULL CHECK (price > 0)
);

CREATE TABLE gacha_items (
    id           BIGSERIAL PRIMARY KEY,
    gacha_id     BIGINT    NOT NULL REFERENCES gachas(id)     ON DELETE CASCADE,
    character_id BIGINT    NOT NULL REFERENCES characters(id) ON DELETE RESTRICT,
    weight       INTEGER   NOT NULL CHECK (weight > 0),
    UNIQUE (gacha_id, character_id)
);

CREATE TABLE user_characters (
    id           BIGSERIAL   PRIMARY KEY,
    user_id      BIGINT      NOT NULL REFERENCES users(id)      ON DELETE CASCADE,
    character_id BIGINT      NOT NULL REFERENCES characters(id) ON DELETE RESTRICT,
    obtained_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_user_characters_user ON user_characters(user_id);

CREATE TABLE sessions (
    token      TEXT        PRIMARY KEY,
    user_id    BIGINT      NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX idx_sessions_user ON sessions(user_id);

seed.sql は characters 12 体 + gachas 2 件 + gacha_items 19 件を INSERT。 リポジトリの db/seed.sql をそのまま流用 OK。

9.3 sqlite3 → psycopg に置き換える

? プレースホルダを %s に変えるなど、 細かな方言差を吸収する作業です。 Ch.5 のコラムで触れたとおり、 ライブラリは違っても発想は同じ。

psycopg をインストール

pip install "psycopg[binary]>=3.1,<4"

server/db.py — Colab の get_conn を psycopg 版に

📄 ~/gacha_gacha/server/db.py 
"""DB 接続ヘルパ (psycopg 版)。"""
import os
from contextlib import contextmanager
import psycopg
from psycopg.rows import dict_row


def _dsn():
    return (
        f"host={os.getenv('PGHOST', 'localhost')} "
        f"port={os.getenv('PGPORT', '5432')} "
        f"dbname={os.getenv('PGDATABASE', 'gacha')} "
        f"user={os.getenv('PGUSER', 'gacha')} "
        f"password={os.getenv('PGPASSWORD', 'gacha')}"
    )


@contextmanager
def get_conn():
    conn = psycopg.connect(_dsn(), row_factory=dict_row, autocommit=False)
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


def healthcheck():
    try:
        with get_conn() as conn, conn.cursor() as cur:
            cur.execute("SELECT 1")
            cur.fetchone()
        return True
    except Exception as e:
        print(f"[db] healthcheck failed: {e}")
        return False

変更点まとめ (sqlite3 → psycopg)

場所sqlite3psycopg
接続sqlite3.connect("gacha.db")psycopg.connect(dsn, row_factory=dict_row)
プレースホルダ?%s
結果型sqlite3.Row + dict()dict_row で初めから dict
カーソルconn から直接 execute 可明示的に conn.cursor() ブロック推奨
RETURNING3.35 以降サポート常時サポート
FOR UPDATE無視 (実質シングルライタ)正式サポート (本番はこれを使う)

my_server.py の SQL を一括置換

エディタの全置換で ? → %s。 ただし「文字列リテラル中の ?」 を誤爆しないよう注意。 正規表現で VALUES \(\? や = \? など SQL 文脈に絞ると安全です。

conn.execute(...) は psycopg にもあるが、 推奨は with conn.cursor() as cur: cur.execute(...)。 行数が増えるので置換規則は: 

# 旧 (sqlite3)
cur = conn.execute("SELECT ... WHERE id = ?", (uid,))
row = cur.fetchone()

# 新 (psycopg)
with conn.cursor() as cur:
    cur.execute("SELECT ... WHERE id = %s", (uid,))
    row = cur.fetchone()

参考実装はリポジトリの server/app.py にあります。 Colab 版と並べて差分を確認しながら 移植するのが楽。

9.5 自動テストを書く

手で全機能を毎回確かめるのは続かない。 機械が代わりにやってくれる形に。 2 種類のテストを足します。

smoke テスト (curl ベースの E2E)

サーバが起動した状態で全 API を順に叩いて、 期待通りに動くか確認する shell スクリプト。 新しい機能を足したあと、 既存が壊れていないかを 1 コマンドで確認できる。

📄 ~/gacha_gacha/tests/smoke_curl.sh 
#!/usr/bin/env bash
# smoke テスト: docker compose up -d && python -m server.app した状態で
#   bash tests/smoke_curl.sh
set -euo pipefail

BASE_URL=${BASE_URL:-http://localhost:8000}
USER_NAME="smoke_$(date +%s)"
PASSWORD="smokepass123"
TOKEN=""

call() {
  local method=$1 path=$2 body=${3:-}
  local args=( -sS -X "$method" -w '\nHTTP_STATUS:%{http_code}\n' "$BASE_URL$path"
               -H "Content-Type: application/json" )
  [ -n "$TOKEN" ] && args+=( -H "Authorization: Bearer $TOKEN" )
  [ -n "$body"  ] && args+=( -d "$body" )
  curl "${args[@]}"
}

# 1) 登録 (token を取り出す)
echo "== register =="
RESP=$(call POST /api/register \
  "{\"name\":\"$USER_NAME\",\"password\":\"$PASSWORD\",\"display_name\":\"Smoker\"}")
echo "$RESP"
TOKEN=$(echo "$RESP" | python3 -c "import json,sys; d=json.loads(sys.stdin.readline()); print(d.get('token',''))")

# 2) /api/me
echo; echo "== me =="
call GET /api/me

# 3) ガチャ一覧 + pull x 3 + box
echo; echo "== gacha list =="
call GET /api/gacha/list

for i in 1 2 3; do
  echo; echo "== pull #$i =="
  call POST /api/gacha/pull '{"gacha_id":1}'
done

echo; echo "== box =="
call GET /api/box

echo; echo "== logout =="
call POST /api/logout

echo; echo "smoke test OK"
chmod +x tests/smoke_curl.sh
bash tests/smoke_curl.sh

ユニットテスト (DB 抜きで純粋関数だけ)

認証ハッシュ + ガチャ抽選分布のように、 DB を要らない純粋関数は単体で速くテストできます。

📄 ~/gacha_gacha/tests/test_unit.py 
"""DB 不要のユニットテスト。  python tests/test_unit.py で実行。"""
import pathlib, sys, random
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent.parent))
from server import auth, gacha

failed = False
def expect(label, cond, detail=""):
    global failed
    print(f"  {'PASS' if cond else 'FAIL'}  {label}", detail if not cond else "")
    failed = failed or (not cond)

print("[auth]")
h = auth.hash_password("hunter2")
expect("正しいパスで verify",   auth.verify_password("hunter2", h))
expect("間違ったパスで reject", not auth.verify_password("HUNTER2", h))
expect("ソルトで毎回違う",       auth.hash_password("a") != auth.hash_password("a"))

print("[gacha]")
pool = [gacha.GachaItem(1, "A", 1, "🟢", 75),
        gacha.GachaItem(2, "B", 5, "🐉", 25)]
rng = random.Random(0)
counts = {1: 0, 2: 0}
for _ in range(10_000):
    counts[gacha.draw(pool, rng=rng).character_id] += 1
expect(f"分布 ≈ 75/25 (実測 {counts[1]/100:.1f}%)", abs(counts[1]/10_000 - 0.75) < 0.02)

print("\n", "FAILED" if failed else "PASSED ✓")
raise SystemExit(1 if failed else 0)
python tests/test_unit.py
