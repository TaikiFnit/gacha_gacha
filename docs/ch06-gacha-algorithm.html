第 6 章 — ガチャ抽選を本実装する

今までずっと /api/gacha/pull はハードコードでドラゴンしか出さない状態でした。 ここでこのシステムの面白い部分—重み付き乱択 + コイン消費 + トランザクション— を本実装します。

4 スパイラルで:

  1. 重み付き乱択を draw() 関数として書く + シミュレーションで分布を確認
  2. ハンドラに組み込む (まだ DB には書かない、 抽選結果だけ返す)
  3. トランザクションでコイン減算 + user_characters INSERT を 1 セットに
  4. 残コイン不足 / 存在しないガチャ ID のエラー処理

Spiral 1 — 重み付き乱択を draw() として書く

アルゴリズムは古典的:

  1. weight の合計を分母にして、 0 〜 total の一様乱数を 1 つ引く
  2. 各キャラの weight を順に足していき、 累積が乱数を超えたところがそのキャラ

Python の random.choices がまさにこれをやってくれます。 ただし「自分の手で書く」 練習として、 累積和版もコメントで併記します。

📄 server/gacha.py (新規) 
"""ガチャ抽選ロジック (Ch.6 で追加)。"""
from __future__ import annotations
import random
from dataclasses import dataclass


@dataclass
class GachaItem:
    character_id: int
    name: str
    rarity: int
    emoji: str
    weight: int


def fetch_pool(conn, gacha_id: int) -> list[GachaItem]:
    """指定ガチャの排出プールを (キャラ情報 + weight) で取ってくる。"""
    with conn.cursor() as cur:
        cur.execute(
            """
            SELECT c.id   AS character_id, c.name, c.rarity, c.emoji,
                   gi.weight
              FROM gacha_items gi
              JOIN characters c ON c.id = gi.character_id
             WHERE gi.gacha_id = %s
             ORDER BY c.rarity, c.id
            """,
            (gacha_id,),
        )
        rows = cur.fetchall()
    return [GachaItem(**r) for r in rows]


def draw(pool: list[GachaItem], rng: random.Random | None = None) -> GachaItem:
    """重み付き乱択を 1 回行う。

    手で書くなら:
        total = sum(item.weight for item in pool)
        r = rng.uniform(0, total)
        acc = 0
        for item in pool:
            acc += item.weight
            if r <= acc:
                return item
    という累積和パターン。 random.choices が同じことをやってくれる。
    """
    if not pool:
        raise ValueError("ガチャに排出設定が 1 件もありません")
    rng = rng or random.SystemRandom()    # 暗号学的乱数
    weights = [item.weight for item in pool]
    return rng.choices(pool, weights=weights, k=1)[0]

Spiral 2 — ハンドラに組み込む (まだ DB 更新無し)

まずは「ガチャを引いて結果を返す」 だけ実装します。 コイン減算と所持品追加は次のスパイラル。 1 つずつ動かす のが鉄則。

📝 my_server.py の gacha_pull を書き換え 
from server.gacha import fetch_pool, draw   # ← ファイル先頭に追加

@route("POST", "/api/gacha/pull")
def gacha_pull(h):
    body = h._read_json()
    gacha_id = body.get("gacha_id")
    if not isinstance(gacha_id, int):
        raise bad_request("gacha_id は整数で指定してください")

    with get_conn() as conn:
        user = h.require_user(conn)        # Ch.5 で作った認証ヘルパ

        # ガチャの存在 + 価格を取る
        with conn.cursor() as cur:
            cur.execute("SELECT id, name, price FROM gachas WHERE id = %s", (gacha_id,))
            g = cur.fetchone()
        if g is None:
            raise not_found("そのガチャは存在しません")

        # プールを取って 1 回引く (まだ DB 更新無し)
        pool = fetch_pool(conn, gacha_id)
        won = draw(pool)

    # まだコイン消費・所持追加していない: 結果は仮で coins = user.coins そのまま
    h._json(200, {
        "gacha":     {"id": g["id"], "name": g["name"], "price": g["price"]},
        "character": {"id": won.character_id, "name": won.name,
                      "rarity": won.rarity, "emoji": won.emoji},
        "obtained_at": "2026-04-26 00:00:00",   # 仮
        "coins": user["coins"],                  # 減算してない
    })

  • ブラウザでログイン → 「引く」 ボタン押下
  • 毎回違うキャラが出る (= 抽選が効いている)
  • レア度に応じて画面の色が変わる (Ch.3 のフロントが rarity を見ている)
  • ただし所持コインが減らない、 Box に増えない (= 次のスパイラル)

Spiral 3 — トランザクションでコイン消費 + Box 追加

ガチャ 1 回の本体は 「coins -100」 と「user_characters に 1 行 INSERT」 の 2 つの書き換え。 これを片方だけ成功させてしまうと「コインだけ減ってキャラ無し」 になる。 トランザクションでまとめます。

さらに「同時に同じユーザーで二重 pull」 が起きたとき、 coins を 2 回引かれて 1 回しか減らないと困るので、 行ロック (FOR UPDATE) も入れます。

📝 gacha_pull を書き換え (本実装) 
@route("POST", "/api/gacha/pull")
def gacha_pull(h):
    body = h._read_json()
    gacha_id = body.get("gacha_id")
    if not isinstance(gacha_id, int):
        raise bad_request("gacha_id は整数で指定してください")

    with get_conn() as conn:
        user = h.require_user(conn)

        with conn.cursor() as cur:
            # ガチャ情報 + 共有ロック (他者も読めるが書けない)
            cur.execute("SELECT id, name, price FROM gachas WHERE id = %s FOR SHARE",
                        (gacha_id,))
            g = cur.fetchone()
            if g is None:
                raise not_found("そのガチャは存在しません")

            # 自分の coins を排他ロックして読む (二重消費防止)
            cur.execute("SELECT coins FROM users WHERE id = %s FOR UPDATE",
                        (user["id"],))
            coins_now = cur.fetchone()["coins"]
            if coins_now < g["price"]:
                raise bad_request(
                    f"コインが足りません (必要 {g['price']} / 所持 {coins_now})"
                )

        # 抽選 (DB 更新前にやる)
        pool = fetch_pool(conn, gacha_id)
        if not pool:
            raise bad_request("そのガチャには排出設定がありません")
        won = draw(pool)

        # 書き換えはまとめて 2 つ: coins 減算 + 履歴 INSERT
        with conn.cursor() as cur:
            cur.execute(
                "UPDATE users SET coins = coins - %s WHERE id = %s RETURNING coins",
                (g["price"], user["id"]),
            )
            new_coins = cur.fetchone()["coins"]

            cur.execute(
                """
                INSERT INTO user_characters (user_id, character_id)
                VALUES (%s, %s) RETURNING obtained_at
                """,
                (user["id"], won.character_id),
            )
            obtained_at = cur.fetchone()["obtained_at"]

    h._json(200, {
        "gacha":     {"id": g["id"], "name": g["name"], "price": g["price"]},
        "character": {"id": won.character_id, "name": won.name,
                      "rarity": won.rarity, "emoji": won.emoji},
        "obtained_at": obtained_at,
        "coins": new_coins,
    })

💡 解説

  • with get_conn() as conn: がトランザクションの境界。 ブロックを抜けるときに自動コミット、 例外で自動ロールバック
  • FOR UPDATE はその行に排他ロックを取る。 同時に別セッションが同じ行を FOR UPDATE しようとするとブロックされる (= 並行 pull の競合を防ぐ)
  • FOR SHARE は読み取り共有ロック。 他のセッションも読めるが、 上書き/削除はできない (= 抽選中に管理画面でガチャ筐体が消されることを防ぐ)
  • 抽選自体 (draw) は DB を触らない純粋関数。 DB 内ロジックではなく Python 側で完結させる方が、 リトライや単体テストがしやすい

🧪 動作確認 — クライマックス

  1. ブラウザでログイン (1000 coin)
  2. 「通常ガチャを引く」 ボタン押下 → コイン 900 / 何かキャラが出る
  3. 連打 → コインがどんどん減る
  4. 10 連の後 → コイン 0 → 次の引きで 「コインが足りません」 (Spiral 4 で正式対応するが既に動く)
  5. psql で SELECT user_id, character_id FROM user_characters ORDER BY id DESC LIMIT 5 → 履歴あり

Spiral 4 — エラー処理を仕上げる

Spiral 3 で残コイン不足 / 存在しないガチャ ID は既にカバー済み。 ここでは 排出設定が 1 件も無いガチャ筐体 があったらどうなるかを念のため確認します。

SQL で実験用の空ガチャを 1 つ作って、 フロントから引いてみる:

📒 psql 
INSERT INTO gachas (name, price) VALUES ('空ガチャ (テスト用)', 100);
-- 排出設定は何もしない

画面リロード → ガチャ一覧に「空ガチャ」 が増える。 引くと 400 が返り、 フィードバックパネルに 「そのガチャには排出設定がありません」。 フロントはサイレント失敗せず、 ちゃんとエラー文言が見えます。

確認できたらテスト用ガチャを片付け:

DELETE FROM gachas WHERE name = '空ガチャ (テスト用)';

本章のまとめ

  • 重み付き乱択は累積和 + 一様乱数。 random.choices(weights=...) がそれを書いてくれる
  • 大数の法則を使って実装の正しさを確認するのが、 統計絡みアルゴリズムの定番手法
  • 「複数の DB 更新を 1 セット」 はトランザクションでくくる。 1 個でも失敗したら全部戻す
  • FOR UPDATE で行ロック → 並行性問題 (二重消費等) を DB に守ってもらう
  • 純粋関数 (抽選) と副作用 (DB 更新) を分けると、 単体テスト・リトライ・差し替えが楽になる
