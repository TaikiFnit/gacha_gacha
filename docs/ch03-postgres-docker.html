第 3 章 — ローカルに移行してフロントから叩く

前章までで HTTP サーバの骨格 と DB のスキーマ が手元に揃いました。 この章でいよいよ ブラウザで動くフロントエンド を登場させ、 フロント → サーバ → DB の 一気通貫の流れ を 1 度回します。

Colab はここで卒業です。 ブラウザで動くフロントを観察するなら、 ローカルで動かす方が断然見やすい (デバッグツール / Network タブが使える)。 ついでに本番想定の PostgreSQL を Docker で起動 しておきます。

📐 この章のゴール

ブラウザで http://localhost:5500 を開いて、 「新規登録」 ボタンを押したらガチャ画面が出る 状態にする。 中身は (まだ DB を使わずに) ハードコードで返すだけだが、 フロント → サーバの往復 が成立する。 次章で DB 接続に置き換える。

必要なもの

  • Python 3.10 以上
  • Docker Desktop (Mac/Windows) もしくは Docker Engine + Compose
  • テキストエディタ (VS Code など)
  • ブラウザ (Chrome/Edge/Firefox/Safari)
  • ターミナル (macOS/Linux はそのまま、Windows は WSL2 推奨)

3.4 サーバ (Ch.1 で育てた完成版) を配置

Notebook の Step 1-G セルからコードを丸ごとコピペして、 ~/gacha_gacha/server/my_server.py として保存します。 Notebook 用の serve() ヘルパは要らないので、 末尾を HTTPServer().serve_forever() に書き換えます。

📄 server/my_server.py (= Ch.1 の最終形 + サーバ起動コードを末尾に) 
import json, traceback
from http.server import BaseHTTPRequestHandler, HTTPServer
from urllib.parse import urlparse, parse_qs

# ----- 例外をステータス付きで投げるための仕掛け (Ch.1 Step 6 と同じ) ------
class AppError(Exception):
    def __init__(self, status, message):
        super().__init__(message)
        self.status, self.message = status, message
def bad_request(msg):  return AppError(400, msg)
def not_found(msg="Not Found"): return AppError(404, msg)
def unauthorized(msg="ログインが必要です"): return AppError(401, msg)

# ----- ルーター辞書 ----------------------------------------------------------
ROUTES = {}
def route(method, path):
    def deco(fn):
        ROUTES[(method.upper(), path)] = fn
        return fn
    return deco

# ----- まずは健康確認だけ ----------------------------------------------------
@route("GET", "/api/health")
def health(h):
    h._json(200, {"status": "ok"})

# ----- ハンドラ基盤 (Ch.1 の集大成 + CORS) ------------------------------------
class App(BaseHTTPRequestHandler):
    def do_GET(self):     self._dispatch("GET")
    def do_POST(self):    self._dispatch("POST")
    def do_OPTIONS(self):
        self.send_response(204)
        self._cors()
        self.send_header("Content-Length", "0")
        self.end_headers()

    def _dispatch(self, method):
        path = urlparse(self.path).path
        handler = ROUTES.get((method, path))
        if handler is None:
            return self._json(404, {"error": "Not Found", "path": path})
        try:
            handler(self)
        except AppError as e:
            self._json(e.status, {"error": e.message})
        except Exception as e:
            traceback.print_exc()
            self._json(500, {"error": "internal server error", "detail": str(e)})

    def _cors(self):
        # フロントが localhost:5500 から叩くため、CORS を明示許可する
        origin = self.headers.get("Origin", "")
        if origin in ("http://localhost:5500", "http://127.0.0.1:5500"):
            self.send_header("Access-Control-Allow-Origin", origin)
            self.send_header("Access-Control-Allow-Credentials", "true")
            self.send_header("Vary", "Origin")
        self.send_header("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
        self.send_header("Access-Control-Allow-Headers", "Content-Type")

    def _read_json(self):
        n = int(self.headers.get("Content-Length", "0"))
        raw = self.rfile.read(n) if n else b""
        try:
            return json.loads(raw.decode("utf-8")) if raw else {}
        except json.JSONDecodeError as e:
            raise bad_request(f"invalid json: {e}")

    def _text(self, status, body):
        b = body.encode("utf-8"); self.send_response(status); self._cors()
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def _json(self, status, obj):
        b = json.dumps(obj, ensure_ascii=False).encode("utf-8")
        self.send_response(status); self._cors()
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b))); self.end_headers(); self.wfile.write(b)

    def log_message(self, fmt, *args):
        import sys
        sys.stderr.write(f"[{self.command}] {self.path} -> {fmt % args}\n")

# ----- 起動 ------------------------------------------------------------------
if __name__ == "__main__":
    addr = ("0.0.0.0", 8000)
    print(f"listening on http://localhost:{addr[1]}")
    print("ルート一覧:")
    for (m, p) in sorted(ROUTES):
        print(f"  {m:5s} {p}")
    HTTPServer(addr, App).serve_forever()

# 別ターミナルで:

3.5 フロント (= 既製品) を配置 — 3 分クッキング

フロントは「学習用に動くガチャ画面 + デバッグコンソール」 が乗った既製品です。 本リポジトリ web/ から 3 ファイル (index.html / app.js / style.css) を ~/gacha_gacha/web/ にコピー。 

cp /path/to/repo/web/index.html ~/gacha_gacha/web/

ブラウザで http://localhost:5500 を開いてください。 画面下に 🔍 デバッグコンソール が常設されています。 ガチャ画面 (UI) は上半分、サーバとの往復はすべて下半分に流れる構造です。

📘 API 仕様書 フロントが期待する API の形は、本サイト内の 📘 API 仕様書 にまとまっています。 この章では仕様書を見ながら、必要な API を 1 つずつサーバに足していく 流れになります。

3.6 初回観察 — 「全 API が無い」 状態でフロントを開く

ブラウザで http://localhost:5500 を開くと、 フロントは起動と同時に GET /api/me を叩きます (= 「あなたログイン中?」 確認)。 でもサーバはまだ /api/me を知らないので、 デバッグコンソールに 赤い 404 が出るはずです。

✅ デバッグコンソールでの観察 
14:30:12 GET /api/me → 404 12ms ✗ 期待形式と違う (1箇所)
   📥 サーバが返した本文 (JSON)
   { "error": "Not Found", "path": "/api/me" }
   📐 期待形式との差分
     user: 期待 object, 実際 undefined

これでわかること: フロントは 「ユーザー情報を返してね」 と聞いているのに、 サーバは 「そんなパス知らない」 と答えている。 → サーバに /api/me を実装していこう。

3.7 第 1 スパイラル: /api/me を「常に 401」 で返す

最小実装: 誰もログインしていない前提で 401 を返す だけ。 フロントはこれを「未ログイン」 と解釈して、登録/ログインフォームを出してくれます。

📝 server/my_server.py に追記 @route("GET", "/api/health") の下に追加: 
@route("GET", "/api/me")
def me(h):
    raise unauthorized()

サーバを Ctrl+C で止めて、再起動:

python server/my_server.py

ブラウザをリロード (or デバッグコンソールの「クリア」ボタン押下後にページ操作)。

✅ 期待される結果
  • デバッグコンソール: GET /api/me → 401 ✗ (期待形式と違う)
  • 画面: 「ログイン or 新規登録」 フォームが表示される

フロントは 200 + user 情報 を期待しています (api-spec.html 参照)。 401 だと shape mismatch と判定され、登録フォームが出る = 期待動作。

3.8 第 2 スパイラル: /api/register を 鸚鵡返し で実装

フォームに alice / secret123 を入れて「新規登録」 ボタンを押します。 これも POST /api/register が無いので 404 で返るはず。 サーバ側で「受け取った body をそのまま返すだけ」 の最小実装を入れます。

📝 server/my_server.py に追記 
@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    print("受け取った body:", body)   # ← サーバログに出る
    h._json(200, {"received": body})  # ← まずは鸚鵡返し

サーバを再起動して、フロントから「新規登録」 ボタンを押す。

✅ 期待される結果
  • サーバのターミナル: 受け取った body: {'name': 'alice', 'password': 'secret123', 'display_name': 'alice'}
  • デバッグコンソール: POST /api/register → 200 ✗ 期待形式と違う (4箇所) (オレンジ色)
  • 画面上の「⚠️ 期待形式の応答が返ってきませんでした」 パネルに、 サーバが返した {"received": {...}} がそのまま表示される

これが最高の学習体験: 「サーバから何が返っているか」 が画面で確認でき、 「フロントが本当はどんな形を期待しているか」 が同じ画面に並ぶ。 仕様書 (api-spec.html) と見比べて、 何を直せば期待形式に届くか考えます。

3.9 第 3 スパイラル: 仕様通りに揃えてみる (まずはハードコード)

仕様: {"user": {"id":数, "name":文字列, "display_name":文字列, "coins":数}}。 DB はまだ繋いでいないので、ハードコードで返してみます。

📝 register ハンドラを書き換え 
@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = body.get("name", "anonymous")
    h._json(200, {
        "user": {
            "id": 1,
            "name": name,
            "display_name": body.get("display_name") or name,
            "coins": 1000,
        }
    })

サーバ再起動 → ブラウザでリロード → 新規登録ボタン押下。

🎉 期待される結果
  • デバッグコンソール: POST /api/register → 200 ✓ 期待形式 (緑色)
  • 画面: 「ようこそ alice さん」「所持コイン: 1000」 とガチャ画面が出る

フロント → サーバの一気通貫が成立しました 🎉。 次のセクションで残りの API もハードコードで埋めて、 ガチャを最後まで通します。

3.10 残り API もハードコードで通す

画面に出たガチャを実際に引いてみると、 POST /api/gacha/pull も GET /api/gacha/list もまだ無いので 404 が出ます。 同じ要領で 1 つずつ実装します。 DB が無いので毎回同じ値を返すだけ。 「形を満たす」 が目的です。

📝 残りのルートを追加 
@route("GET", "/api/gacha/list")
def gacha_list(h):
    h._json(200, {"gachas": [
        {"id": 1, "name": "通常ガチャ",      "price": 100, "pool_size": 12, "total_weight": 505},
        {"id": 2, "name": "プレミアムガチャ", "price": 300, "pool_size":  7, "total_weight": 175},
    ]})

@route("POST", "/api/gacha/pull")
def gacha_pull(h):
    body = h._read_json()
    h._json(200, {
        "gacha":     {"id": body.get("gacha_id", 1), "name": "通常ガチャ", "price": 100},
        "character": {"id": 10, "name": "ドラゴン", "rarity": 5, "emoji": "🐉"},
        "obtained_at": "2026-04-26 14:30:00+00:00",
        "coins": 900,
    })

@route("GET", "/api/box")
def box(h):
    h._json(200, {
        "user": {"id": 1, "name": "alice", "display_name": "alice", "coins": 900},
        "total_pulls": 1,
        "items": [{
            "id": 10, "name": "ドラゴン", "rarity": 5, "emoji": "🐉", "count": 1,
            "first_obtained_at": "2026-04-26 14:30:00+00:00",
            "last_obtained_at":  "2026-04-26 14:30:00+00:00",
        }],
    })

@route("POST", "/api/login")
def login(h):
    body = h._read_json()
    h._json(200, {"user": {"id": 1, "name": body.get("name", "alice"),
                            "display_name": body.get("name", "alice"), "coins": 1000}})

@route("POST", "/api/logout")
def logout(h):
    h._json(200, {"ok": True})

サーバ再起動 → ブラウザでリロード → 新規登録 → 「引く」ボタン押下。

🎉 期待される結果
  • 登録 → ガチャ画面 → 「引く」 → 必ず ドラゴン (★★★★★) が出る (笑)
  • Box にドラゴンが 1 体入る
  • デバッグコンソールがすべての往復で緑色 ( ✓ 期待形式)

3.11 ハードコードの限界と次章への橋渡し

ガチャを 5 回引いても 10 回引いても、 必ずドラゴンが出ます。 コインも常に 900。 これは当然です — サーバは body を見ずに固定値を返しているだけだから。

でも仕組みとしては:

  • フロントが叩く API のパスはこれで全部 (= 仕様書通り)
  • 応答 shape はフロントの期待と一致 (= 緑色)
  • あとは「サーバ側で本当のロジックを書く」 だけ

次章 (Ch.4) では register ハンドラの中で PostgreSQL に INSERT INTO users ... を発行し、 RETURNING id で実 id を取り、 結果を "user" に詰めて返すように書き換えます。 ハードコード → DB 連携の 1 ハンドラずつスパイラル を回していきます。
