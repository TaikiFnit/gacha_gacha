第 3 章 — PostgreSQL を Docker で動かす

この章では、ローカルマシンを汚さずに PostgreSQL を立ち上げて、 db/schema.sql と db/seed.sql が初回起動で自動投入される 仕組みを理解します。

学習目標

  • Docker / コンテナ / イメージ / ボリュームの違いを説明できる
  • docker-compose.yml の各キーが何を意味するか言える
  • 初期化スクリプトの実行順序 (/docker-entrypoint-initdb.d) を理解する
  • データを残す/消すの操作を切り分けられる (down vs down -v)

扱うトピック

  1. そもそもなぜ DB はコンテナで動かすのか (環境再現性 / OS差吸収)
  2. docker compose up -d で起きていること
  3. ポート公開 / ボリュームマウント / 環境変数 / ヘルスチェック
  4. Postgres の POSTGRES_* 環境変数
  5. 初期化スクリプトの仕様と落とし穴 (2 回目以降は実行されない)
  6. psql コンテナ内/ホストから接続する方法 2 通り
  7. 運用 Tips: データを壊して作り直すワンライナー

参照コード

  • docker-compose.yml
  • db/schema.sql / db/seed.sql

演習の例

  1. コンテナを起動 → 停止 → ボリュームを残したまま再起動。データが残ることを確認
  2. schema.sql を変更してから docker compose up を再実行 → 反映されないことを確認
  3. docker compose down -v でボリュームごと消し、再投入されるか確認
  4. docker compose exec db psql 経由で SQL を実行
