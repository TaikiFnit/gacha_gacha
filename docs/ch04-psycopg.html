Chapter 4 所要時間: 90〜120 分 形式: ハンドラを 1 つずつ DB 接続に置き換え

第 4 章 — psycopg で本物の DB に繋ぐ

前章で my_server.py はフロントの期待通り応答するようになりました。 でも全員 id=1、毎回ドラゴン、ブラウザ閉じたら全部リセット。 ここから 1 ハンドラずつ、 PostgreSQL に本物の SQL を投げる形に書き換えていきます。 レスポンス shape はそのまま、中身だけ実DBに差し替えるスパイラル。

📐 進め方

各スパイラルで:

  1. Ch.3 で書いた ハンドラの body を SQL 版に書き換える
  2. サーバを再起動 (Ctrl+C → python server/my_server.py)
  3. ブラウザでフロントから操作する
  4. デバッグコンソールが ✓ 期待形式 のままであること、 psql で 実際に DB が変わったこと を両方確認

shape を変えなければ、フロントは何も気にせず動き続けます。 これが 「API は契約 (= shape)」 の効力。 サーバ内部はあとからいくらでも変えられる。

4.1 psycopg をインストールする

psycopg は PostgreSQL 用の Python ドライバです。 v3 系 (パッケージ名 psycopg) を使います。 [binary] を付けるとビルド済みバイナリが入って楽。

📒 ターミナル

python -m venv .venv && source .venv/bin/activate    # 既に入っていればスキップ
pip install "psycopg[binary]>=3.1,<4"

4.2 接続ヘルパを書く: server/db.py

毎回接続文字列を組み立てるのは面倒なので、 「DB を 1 接続して、 with ブロックを抜けるときに自動コミット (失敗時は自動ロールバック)」 を 1 関数にまとめておきます。

📄 server/db.py (新規) 
"""DB 接続ヘルパー。

with get_conn() as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT 1")
        cur.fetchone()
ブロックを抜けるときに自動コミット (例外時は自動ロールバック)。
"""
import os
from contextlib import contextmanager

import psycopg
from psycopg.rows import dict_row


def _dsn() -> str:
    """環境変数を見て、無ければ docker-compose のデフォルトを使う。"""
    return (
        f"host={os.getenv('PGHOST', 'localhost')} "
        f"port={os.getenv('PGPORT', '5432')} "
        f"dbname={os.getenv('PGDATABASE', 'gacha')} "
        f"user={os.getenv('PGUSER', 'gacha')} "
        f"password={os.getenv('PGPASSWORD', 'gacha')}"
    )


@contextmanager
def get_conn():
    # row_factory=dict_row で結果が辞書になる (= JSON 化しやすい)
    conn = psycopg.connect(_dsn(), row_factory=dict_row, autocommit=False)
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()


def healthcheck() -> bool:
    """DB に届くか確認。サーバ起動時の早期失敗用。"""
    try:
        with get_conn() as conn, conn.cursor() as cur:
            cur.execute("SELECT 1")
            cur.fetchone()
        return True
    except Exception as e:
        print(f"[db] healthcheck failed: {e}")
        return False

Spiral 1 — /api/register を本物の INSERT に

Ch.3 のハードコード: 

@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = body.get("name", "anonymous")
    h._json(200, {"user": {
        "id": 1, "name": name,
        "display_name": body.get("display_name") or name,
        "coins": 1000,
    }})

これを実 DB に書き換えます。 users テーブルに INSERT して、 採番された id を RETURNING で受け取る。 Ch.2 で書いたあのテーブル定義がいよいよ本番投入。

📝 register ハンドラを書き換え 
@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    password = body.get("password") or ""
    display_name = (body.get("display_name") or "").strip() or name

    # ----- 入力バリデーション (DB に届く前にやる) -----
    if len(name) < 3 or len(name) > 32:
        raise bad_request("name は 3〜32 文字")
    if len(password) < 6:
        raise bad_request("password は 6 文字以上")

    # ----- DB へ INSERT -----
    # ⚠️ 学習用に password を平文で入れている。 Ch.5 でハッシュ化する。
    with get_conn() as conn:
        with conn.cursor() as cur:
            # 同じ name が既にあるか先に確認 (UNIQUE 制約があるので INSERT しても弾かれるが、
            # エラーメッセージを分かりやすく返したいのでこの順)
            cur.execute("SELECT 1 FROM users WHERE name = %s", (name,))
            if cur.fetchone():
                raise bad_request("その name は既に使われています")

            cur.execute(
                """
                INSERT INTO users (name, pass_hash, display_name)
                VALUES (%s, %s, %s)
                RETURNING id, name, display_name, coins
                """,
                (name, password, display_name),   # ← password は仮で平文
            )
            user = cur.fetchone()

    h._json(200, {"user": user})

💡 解説

  • %s は psycopg のプレースホルダ。 絶対に文字列連結で SQL を組まない (= SQL インジェクション対策)。 たとえば name = "'; DROP TABLE users;--" が来ても安全
  • RETURNING id, name, display_name, coins で、 INSERT した行を 1 撃で返してもらう
  • row_factory=dict_row なので cur.fetchone() がそのまま JSON にできる辞書
  • ハンドラ内で raise bad_request("...") すると、 Ch.1 で作った _dispatch が 400 + JSON エラーに変換してくれる

🧪 動作確認

サーバを再起動して、 ブラウザで「新規登録」 を試します。

✅ 期待される結果
  • デバッグコンソール: POST /api/register → 200 ✓ 期待形式
  • ガチャ画面が出る (Ch.3 と同じ)
  • でも今回は DB に永続化されている!

ターミナルで psql を開いて確認:

docker compose exec db psql -U gacha -d gacha -c "SELECT id, name, display_name, coins, created_at FROM users"

登録した行が見えるはずです。 もう一度同じ name で登録しようとすると、 400 「その name は既に使われています」 が返ります。 フロントの「⚠️ 入力エラー (サーバが弾きました)」 フィードバックがそれを表示します。

📝 自分でちょっと変えてみる

  • UNIQUE 事前チェック (SELECT 1 FROM users WHERE name = %s) を消したらどうなる? → INSERT で psycopg.errors.UniqueViolation が飛ぶ。 まだ補足してないので 500 になる。 補足コードを書いてみよう (try/except)
  • name を "'; DROP TABLE users; --" にして登録してみる (フロントの input maxlength を一旦外して)。 何も起こらないことを確認 → プレースホルダの威力

Spiral 2 — /api/login を本物の SELECT に

ログインも同じ要領。 name で SELECT して、 該当行があれば user 情報を返し、 無ければ 401。 パスワード検証は Ch.5 で扱うので、 ここでは name 一致だけでログインを通します (= 怖い実装だが、 段階的に直す)。

📝 login ハンドラを書き換え 
@route("POST", "/api/login")
def login(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    # ⚠️ Ch.5 でパスワード検証 (pass_hash と verify_password) を入れる

    with get_conn() as conn, conn.cursor() as cur:
        cur.execute(
            "SELECT id, name, display_name, coins FROM users WHERE name = %s",
            (name,),
        )
        user = cur.fetchone()
    if user is None:
        raise AppError(401, "name か password が違います")
    h._json(200, {"user": user})

🧪 動作確認

  • 登録済みの alice でログイン → 通る
  • 未登録の bob でログイン → デバッグコンソール 401、 画面に「❌ 認証が通りませんでした」
  • パスワードを何にしても登録済み name なら通る (Ch.5 で直す)

Spiral 3 — /api/gacha/list を本物の SELECT JOIN に

ハードコードの 2 件固定を、 実 DB の gachas + gacha_items から取って返す形に。 JOIN + GROUP BY + COUNT がまさに第2章でやったやつ。

📝 gacha_list ハンドラを書き換え 
@route("GET", "/api/gacha/list")
def gacha_list(h):
    with get_conn() as conn, conn.cursor() as cur:
        cur.execute("""
            SELECT g.id, g.name, g.price,
                   COUNT(gi.id)               AS pool_size,
                   COALESCE(SUM(gi.weight), 0) AS total_weight
              FROM gachas g
              LEFT JOIN gacha_items gi ON gi.gacha_id = g.id
             GROUP BY g.id
             ORDER BY g.id
        """)
        rows = cur.fetchall()
    h._json(200, {"gachas": rows})

💡 解説

  • LEFT JOIN なので、 排出設定が 1 件もないガチャ筐体があっても落ちない (pool_size=0 で返る)
  • GROUP BY g.id + COUNT(gi.id) で各ガチャの排出キャラ数を出す
  • COALESCE(SUM(gi.weight), 0) で「合計が NULL なら 0」
  • cur.fetchall() は list[dict] なので、 JSON にそのまま入れられる

🧪 動作確認

ブラウザでログイン後、 ガチャ画面に 2 つの筐体が出ているはずです。

✅ デバッグコンソール 
GET /api/gacha/list → 200 ✓ 期待形式
   📥 サーバが返した本文 (JSON)
   {
     "gachas": [
       { "id": 1, "name": "通常ガチャ",     "price": 100, "pool_size": 12, "total_weight": "505" },
       { "id": 2, "name": "プレミアムガチャ", "price": 300, "pool_size":  7, "total_weight": "175" }
     ]
   }

⚠️ total_weight が文字列 "505" になっているのは、 PostgreSQL の SUM が numeric 型を返し、 psycopg がそれを Decimal として扱い、 JSON 化時に str に変換するため。 フロントの shape チェックは pool_size: number だけ見ているので問題なく ✓ になります。

4.6 まだ残ってるもの — 次章への橋渡し

ガチャ画面で「引く」ボタンを押すと、 まだハードコードのままなので毎回ドラゴンが出ます。 Box も同じ。 これらは「誰の操作か」 を知る必要があるため、 セッション (Cookie + sessions テーブル) が必要です。 これが Ch.5 で扱う話。

  • Ch.5: pass_hash でパスワードハッシュ化、 Cookie でセッション、 /api/me と /api/logout を本物に
  • Ch.6: /api/gacha/pull を本物の重み付き乱択 + コイン消費 + トランザクション
  • Ch.7: /api/box を本物の JOIN + GROUP BY + 集計

本章のまとめ

  • psycopg は connection → cursor → execute の流れで SQL を発行する
  • パラメータは必ず %s プレースホルダ。 文字列連結は SQL インジェクションの温床
  • RETURNING で INSERT/UPDATE の結果をそのまま受け取れる (PostgreSQL の便利機能)
  • shape を維持したままハンドラ内部だけ実DBに置き換えれば、 フロントは何も変わらない = API が「契約」 として機能している証
  • UNIQUE / NOT NULL / CHECK は DB が自動で守ってくれるので、 アプリは「分かりやすいエラーに変換する」 だけで済む
