Chapter 2 所要時間: 90〜120 分 形式: Colab セルで sqlite3 を直接動かす

第 2 章 — データベース基礎をColabで設計する

第1章で君の HTTP サーバができた。今度は中身を入れる箱、データベースを Colab セルで 1 テーブルずつ建てていきます。 この章を抜けると、ガチャシステムのデータ層 (5 テーブル) が君の手元に揃います。 第3章以降では、この DB に対して第1章のサーバから SQL を投げる形に進化させていきます。

📐 進め方

本章は Python の sqlite3 モジュール を使います。 SQLite は Python に最初から入っており、Colab でも追加インストール無しで動きます。

本番想定の PostgreSQL と SQLite では一部記法が違いますが、本章で扱う範囲は ほぼ同じです。違いが出る所は都度補足します。

準備 — DB 接続を 1 つ作って使い回す

最初のセルでインメモリの SQLite に接続し、表示ヘルパ run() を定義します。 以降のセルではこの conn をそのまま使い続けるので、ノートブックを再起動したら 上から実行し直してください。

📒 セル G 
import sqlite3

conn = sqlite3.connect(":memory:")
conn.isolation_level = None  # 暗黙トランザクションを止め、BEGIN/COMMIT を自分で書く
conn.execute("PRAGMA foreign_keys = ON")  # SQLite は既定OFF。FK を効かせる

import unicodedata
def _w(s):  # East-Asian-Wide 文字を 2、それ以外を 1 として表示幅を計算
    return sum(2 if unicodedata.east_asian_width(c) in "WF" else 1 for c in str(s))
def _pad(s, n):
    return str(s) + " " * max(0, n - _w(s))

def run(sql, params=()):
    """SQL 実行ヘルパ。SELECT なら結果を表で表示する。"""
    cur = conn.execute(sql, params)
    if cur.description:
        cols = [d[0] for d in cur.description]
        rows = cur.fetchall()
        widths = [max(_w(cols[i]), *(_w(r[i]) for r in rows) if rows else (0,))
                  for i in range(len(cols))]
        print(" | ".join(_pad(c, widths[i]) for i, c in enumerate(cols)))
        print("-+-".join("-" * w for w in widths))
        for row in rows:
            print(" | ".join(_pad(v, widths[i]) for i, v in enumerate(row)))
        print(f"({len(rows)} rows)")
    else:
        print(f"OK ({cur.rowcount} rows affected)")

print("DB connected.")

Step 3 — ガチャ筐体 + 排出設定 (多対多 + 重み)

「ガチャ筐体」と「キャラ」は多対多の関係。 これを RDB で表現する常套手段が 中間テーブル。 さらに今回はそこに weight (重み) も持たせます。

📒 セル K 
run('''
CREATE TABLE gachas (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    name  TEXT    NOT NULL UNIQUE,
    price INTEGER NOT NULL CHECK (price > 0)
)
''')

run('''
CREATE TABLE gacha_items (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    gacha_id     INTEGER NOT NULL REFERENCES gachas(id)     ON DELETE CASCADE,
    character_id INTEGER NOT NULL REFERENCES characters(id) ON DELETE RESTRICT,
    weight       INTEGER NOT NULL CHECK (weight > 0),
    UNIQUE (gacha_id, character_id)
)
''')

conn.executemany("INSERT INTO gachas (name, price) VALUES (?, ?)",
                 [('通常ガチャ', 100), ('プレミアムガチャ', 300)])

# 通常ガチャ: 全レア度をバランス良く配置
conn.execute('''
INSERT INTO gacha_items (gacha_id, character_id, weight)
SELECT g.id, c.id,
       CASE c.rarity WHEN 1 THEN 60 WHEN 2 THEN 30
                     WHEN 3 THEN 20 WHEN 4 THEN 8  WHEN 5 THEN 2 END
  FROM gachas g, characters c
 WHERE g.name = '通常ガチャ'
''')

# プレミアム: レア度3以上のみ、SSR 厚め
conn.execute('''
INSERT INTO gacha_items (gacha_id, character_id, weight)
SELECT g.id, c.id,
       CASE c.rarity WHEN 3 THEN 50 WHEN 4 THEN 20 WHEN 5 THEN 10 END
  FROM gachas g, characters c
 WHERE g.name = 'プレミアムガチャ' AND c.rarity >= 3
''')

# 排出表 (確率付き)
run('''
SELECT g.name AS gacha, c.name AS chara, c.rarity, gi.weight,
       round(gi.weight * 100.0 / sum(gi.weight) over (partition by g.id), 2) AS pct
  FROM gacha_items gi
  JOIN gachas g     ON g.id = gi.gacha_id
  JOIN characters c ON c.id = gi.character_id
 ORDER BY g.id, gi.weight DESC
''')

通常ガチャ       | ナイト   | 3      | 20     | 16.67

💡 解説

  • UNIQUE (gacha_id, character_id) = 複合ユニーク制約。 「同じガチャに同じキャラが 2 行」 を DB レベルで禁止
  • ON DELETE CASCADE = 親 (ガチャ) を消したら子 (排出設定) も連れて消える
  • ON DELETE RESTRICT = 子 (排出に登場している) があるなら親 (キャラ) を消させない
  • SUM(weight) OVER (PARTITION BY g.id) = ウィンドウ関数。 「集計しつつ、行は潰さない」のがミソ

📝 自分でやってみる

  • 同じ (gacha_id, character_id) を二重に INSERT → UNIQUE 違反
  • 存在しない gacha_id を INSERT → FK 違反
  • DELETE FROM characters WHERE id = 1 → ON DELETE RESTRICT で守られる

Step 4 — `user_characters` + トランザクション

ガチャを 1 回引く処理は「coins -100」と「履歴に 1 行 INSERT」 の 2 つの書き換え。 これを両方成功 or 両方失敗で束ねるのがトランザクションです。

📒 セル L 
run('''
CREATE TABLE user_characters (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL REFERENCES users(id)      ON DELETE CASCADE,
    character_id INTEGER NOT NULL REFERENCES characters(id) ON DELETE RESTRICT,
    obtained_at  TEXT    NOT NULL DEFAULT (datetime('now'))
)
''')
run("CREATE INDEX idx_user_characters_user ON user_characters(user_id)")

# alice が通常ガチャを 1 回引いてスライムが当たった、を SQL で再現
conn.execute("BEGIN")
conn.execute("UPDATE users SET coins = coins - 100 WHERE name = 'alice'")
conn.execute('''
INSERT INTO user_characters (user_id, character_id)
SELECT u.id, c.id FROM users u, characters c
 WHERE u.name = 'alice' AND c.name = 'スライム'
''')
conn.execute("COMMIT")

run("SELECT name, coins FROM users WHERE name = 'alice'")
run('''
SELECT u.name AS user, c.name AS chara, uc.obtained_at
  FROM user_characters uc
  JOIN users      u ON u.id = uc.user_id
  JOIN characters c ON c.id = uc.character_id
''')

💡 解説

  • BEGIN ... COMMIT で 2 つの書き換えを 1 セットにまとめた
  • もし UPDATE 後の INSERT が失敗したら、conn.execute("ROLLBACK") で UPDATE もろとも巻き戻せる (= 「コインだけ減ってキャラが配られない」事故を防ぐ)
  • 本物の server/app.py では、Python 側の with get_conn() as conn: がブロック終了時に自動で COMMIT、例外なら ROLLBACK してくれる

Step 5 — JOIN + GROUP BY + ウィンドウ関数で Box を出す

所持品 (Box) を SQL 1 本で組み立てます。 alice にもう少し引かせてからやってみましょう。

📒 セル M 
# まずは alice にあと何回か引かせる (コイン無制限化してテスト)
draws = ['スライム', 'ウルフ', 'スライム', 'ナイト',
         'ウルフ', 'ペガサス', 'スライム', 'ナイト']
for chara in draws:
    conn.execute('''
        INSERT INTO user_characters (user_id, character_id)
        SELECT u.id, c.id FROM users u, characters c
         WHERE u.name = 'alice' AND c.name = ?
    ''', (chara,))
conn.commit()

print("== alice の Box (所持キャラ + 個数) ==")
run('''
SELECT c.name, c.rarity, c.emoji, COUNT(*) AS count
  FROM user_characters uc
  JOIN characters c ON c.id = uc.character_id
  JOIN users      u ON u.id = uc.user_id
 WHERE u.name = 'alice'
 GROUP BY c.id
 ORDER BY c.rarity DESC, c.id
''')

print("\n== 全キャラ × alice の所持数 (LEFT JOIN: 未所持も並べる) ==")
run('''
SELECT c.name, c.rarity, COUNT(uc.id) AS owned
  FROM characters c
  LEFT JOIN user_characters uc
         ON uc.character_id = c.id
        AND uc.user_id = (SELECT id FROM users WHERE name='alice')
 GROUP BY c.id
 ORDER BY c.rarity DESC, c.id
''')

💡 解説

  • JOIN = テーブル同士を「キーで繋いで横に並べる」操作
  • GROUP BY c.id + COUNT(*) = 同じキャラごとに行をまとめて個数を数える
  • LEFT JOIN = 左 (characters) は必ず残す。マッチしない右 (uc) は NULL
  • COUNT(uc.id) は NULL を数えないので、未所持キャラの owned が 0 になる (これが COUNT(*) だと 1 になって嘘になる、よくある罠)

Step 6 — わざと制約に殴られる演習

最後に、これまで作った制約を わざと違反させて DB が何を守ってくれているのか身体で覚えます。

📒 セル N 
def try_sql(label, sql):
    try:
        conn.execute(sql)
        conn.commit()
        print(f"  {label}: ★成功してしまった (制約が抜けてる)")
    except Exception as e:
        print(f"  {label}: {type(e).__name__}: {e}")

print("== それぞれエラーメッセージを読み取る ==")
try_sql("name 重複",        "INSERT INTO users (name, pass_hash) VALUES ('alice', 'h')")
try_sql("rarity=9",         "INSERT INTO characters (name, rarity, emoji) VALUES ('boss', 9, '😈')")
try_sql("weight=0",         "INSERT INTO gacha_items (gacha_id, character_id, weight) VALUES (1, 1, 0)")
try_sql("FK 違反",          "INSERT INTO gacha_items (gacha_id, character_id, weight) VALUES (9999, 1, 1)")
try_sql("ON DELETE RESTRICT","DELETE FROM characters WHERE id = 1")  # 所持されている

# トランザクションの ROLLBACK
print("\n== ROLLBACK の体験 ==")
conn.execute("BEGIN")
conn.execute("INSERT INTO users (name, pass_hash) VALUES ('eve', 'h')")
print("  eve を 1 回入れた → ", conn.execute("SELECT COUNT(*) FROM users WHERE name='eve'").fetchone())
conn.execute("ROLLBACK")
print("  ROLLBACK 後      → ", conn.execute("SELECT COUNT(*) FROM users WHERE name='eve'").fetchone(),
      "(入っていない)")
✅ 期待される出力 
== それぞれエラーメッセージを読み取る ==

  rarity=9: IntegrityError: CHECK constraint failed: rarity BETWEEN 1 AND 5
  weight=0: IntegrityError: CHECK constraint failed: weight > 0

  ROLLBACK 後      →  (0,) (入っていない)

💡 解説

  • 制約違反は例外として返ってくる。 アプリは try/except で受けて、ユーザーには分かりやすいエラーに変えて返す
  • 本物の POST /api/register でも、name 重複は最終的にこの UNIQUE constraint failed を 400 + 「その name は既に使われています」 に変換しているだけ
  • ROLLBACK は「直前の BEGIN 以降全部巻き戻る」 = ガチャ処理の安全網

仕上げ — 育てた DB を持ち帰る

ここまでで作った 5 テーブル (users / characters / gachas / gacha_items / user_characters) は、第3章以降でガチャ API が使う土台そのものです。 消えないように DDL を 1 つの SQL ファイルに書き出して 保存しておきましょう。

📒 セル O — schema.sql / seed.sql に書き出す 
import os, pathlib

# 第0章で作ったROOTディレクトリ配下に書き出す
db_dir = pathlib.Path(os.environ.get("HOME", ".")) / "gacha_gacha" / "db" \
         if pathlib.Path("/content").exists() == False else pathlib.Path("/content/gacha_gacha/db")
# (セル1で os.chdir(ROOT) しているので相対パスでもOK)
db_dir = pathlib.Path("db"); db_dir.mkdir(exist_ok=True)

# DDL (テーブル定義) を sqlite_master から取り出す
ddl_lines = []
for row in conn.execute("""
    SELECT sql FROM sqlite_master
     WHERE type IN ('table', 'index') AND sql IS NOT NULL
     ORDER BY type DESC, name
"""):
    ddl_lines.append(row[0] + ";\n")
schema_sql = "-- 第2章で君が育てた DDL\n\n" + "\n".join(ddl_lines)

# データ (キャラ、ガチャ、排出設定) を INSERT 文として書き出す
seed_lines = ["-- 第2章で投入したマスタデータ\n"]
for table in ["characters", "gachas", "gacha_items"]:
    cols = [d[0] for d in conn.execute(f"SELECT * FROM {table} LIMIT 0").description]
    for row in conn.execute(f"SELECT * FROM {table} ORDER BY id"):
        vals = ", ".join("NULL" if v is None
                         else f"'{str(v).replace(chr(39), chr(39)*2)}'" if isinstance(v, str)
                         else str(v) for v in row)
        seed_lines.append(f"INSERT INTO {table} ({', '.join(cols)}) VALUES ({vals});\n")
seed_sql = "".join(seed_lines)

(db_dir / "schema.sql").write_text(schema_sql, encoding="utf-8")
(db_dir / "seed.sql").write_text(seed_sql, encoding="utf-8")
print("書き出した:")
print(" ", (db_dir / "schema.sql").resolve())
print(" ", (db_dir / "seed.sql").resolve())
print()

print((db_dir / "schema.sql").read_text()[:200])

本章のまとめ

  • テーブルは「同じ事実を 1 箇所だけに」分けて持つ (= 正規化)
  • 多対多は中間テーブルで表現。重みや状態を中間に持てるのが強み
  • NOT NULL / UNIQUE / CHECK / FK はアプリコードの代わりに DB が守ってくれる
  • 複数行の更新が一塊なら必ずトランザクション (BEGIN..COMMIT)
  • JOIN / GROUP BY / ウィンドウ関数まで使えると、ビジネスロジックの大半は SQL で書ける
