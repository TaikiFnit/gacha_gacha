第 16 章 — フロントの本気化

Ch.4 で足した web/ 配下のフロントは「サーバの素の応答が見える」 が目的の学習モード版です。 本物のゲーム UI に育てるには、 SPA 化 + リアルタイム通知 + 演出アニメを入れることになります。 ただし「API 仕様は変えない」のが本章で一番大事な約束です。

16.1 学習モード版の何が足りないか

web/index.html + web/app.js はわざとシンプルに書いてあります。 意図は「 fetch すると何が返ってきて、 それが画面のどこに反映されるか」が ソースコードを読めば追える、 ということ。 本番ゲーム UI として足りないのは:

  • 状態管理: ログイン状態、 所持コイン、 Box の中身を画面間で共有する仕組みが無い
  • ルーティング: ?screen=box 的な切り替えで擬似ページ遷移できない
  • 演出: ガチャ抽選中の暗転 / レア確定の光り方が無い
  • リアルタイム性: 他人がガチャを引いたことを知る術が無い

16.2 SPA 化の設計判断

React / Vue / Svelte のどれを選ぶかは好みですが、 サーバ側との接点は どれを選んでも同じです: 

// api.ts — どのフレームワークでも、 ここだけは同じ
export async function pull(gachaId: number): Promise<PullResult> {
  const res = await fetch("/api/gacha/pull", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${getToken()}`,
    },
    body: JSON.stringify({ gacha_id: gachaId }),
  });
  if (!res.ok) throw new Error((await res.json()).error);
  return res.json();
}

このapi.ts (or api.js) を 1 つのファイルに集約するのが鍵。 フレームワークを差し替えても、 サーバとの会話を担う層は隔離されている状態を保つ。

状態管理

  • React: Zustand / Jotai (シンプル) または Redux Toolkit (定番)
  • Vue: Pinia
  • Svelte: stores が言語組込み

ガチャゲームの状態は「ユーザー (coins, name) + Box (所持キャラ) + 進行中の演出フラグ」 くらい。 大きなツールに振り回されないことの方が大事で、 100 行で書ける store で十分です。

16.3 WebSocket でリアルタイム通知

「他のユーザーが SSR を引いた!」 をタイムラインで流すと、 一気にソシャゲ感が出ます。 Python 標準の http.server は WebSocket を喋らないので、 別プロセスで websockets ライブラリを立ち上げるのが現実的: 

import asyncio, json
import websockets

clients = set()

async def broadcast(payload):
    msg = json.dumps(payload, ensure_ascii=False)
    await asyncio.gather(*(c.send(msg) for c in clients), return_exceptions=True)

async def handler(ws):
    clients.add(ws)
    try:
        async for _ in ws:
            pass   # クライアントからの送信は使わない
    finally:
        clients.discard(ws)

async def main():
    async with websockets.serve(handler, "0.0.0.0", 8765):
        await asyncio.Future()

API サーバから WS サーバへは「内部 HTTP で 1 イベント POST」 → WS サーバが broadcast()、 が一番シンプル。 同じプロセスで両方持つなら asyncio 系のフレームワークに 乗り換えることになります (Starlette など)。

SSE という選択肢

クライアントへの一方向通知だけなら、 WebSocket より SSE (Server-Sent Events) の方が簡単です。 HTTP レスポンスを Content-Type: text/event-stream で 開きっぱなしにして、 サーバから data: ...\n\n を流すだけ。 http.server でも書けます。

16.4 ガチャ演出アニメ

演出はサーバ側で確定した結果を、 フロントが「あえて遅らせて出す」ことで生まれます: 

async function pullWithEffect(gachaId: number) {
  // 1. サーバに結果を取りに行く (これが一瞬で終わる)
  const result = await pull(gachaId);

  // 2. 暗転 (CSS transition) → 1.5s 待つ
  await playIntro();

  // 3. 結果の rarity に応じて光らせる
  if (result.character.rarity >= 5) await playSsrEffect();
  else if (result.character.rarity >= 4) await playSrEffect();

  // 4. 結果カードを表示
  showCard(result.character);
}

結果は最初に確定しているのがポイント。 演出の途中で「実はもう一度抽選してる」 みたいな実装は、 表示と内部状態がズレて事故ります。

16.5 「API は契約」 — フロント刷新時の安全網

フロントを React で書き直す、 SPA 化する、 演出を入れる — どれもサーバを触らずに 実装できるはずです。 そこを守るために、 サーバ側にAPI smoke テスト を残します。 

# scripts/ch16_api_smoke.py の抜粋
URL = "http://127.0.0.1:8000"
def post(path, body, token=None):
    headers = {"Content-Type": "application/json"}
    if token:
        headers["Authorization"] = f"Bearer {token}"
    r = urllib.request.Request(
        URL + path, data=json.dumps(body).encode(),
        headers=headers, method="POST",
    )
    with urllib.request.urlopen(r) as res:
        return res.status, json.loads(res.read())

# 1. 登録 + ログイン
status, _ = post("/api/register", {"name": "smoke", "password": "p"})
assert status == 200
status, body = post("/api/login", {"name": "smoke", "password": "p"})
token = body["token"]

# 2. ガチャを引く
status, body = post("/api/gacha/pull", {"gacha_id": 1}, token=token)
assert status == 200
assert "character" in body and "rarity" in body["character"]

この smoke テストが通る限り、 サーバ側の API 互換性は守られている。 フロントは この契約に従っていれば、 React で書こうが Vue で書こうが動く。

16.6 学習の旅の終わり、 そして始まり

ここまで通ったあなたは、 もう 「Web バックエンド + RDB がどう動いているか」を フレームワーク無しで自分の手で組み上げ、 拡張機能 7 つ (ログインボーナス / アイドル風 / ピックアップ / SNS / マイグレーション / 監視 / フロント) の運用を体で知った状態です。

  • HTTP の中身が見える
  • SQL を直接書ける
  • 並行性 (FOR UPDATE / トランザクション / UNIQUE 制約) で守れる
  • 本番のスキーマ変更を段階デプロイで安全に進められる
  • 運用データ (ログ / メトリクス / probe) を仕込める
  • API 仕様を契約として、 フロントとサーバを独立に進化させられる

この後、 Django や FastAPI、 Next.js を触ったとき、 「あぁ、 これは ROUTES 辞書を 綺麗に書いただけ」 「これは collect() を ORM のフックに移しただけ」と 全部透けて見えます。 道具選びの話で、 もう怖くない。

ガチャを伸ばすも良し、 全く別のサービスに応用するも良し。 この教材は完。 でも、 あなたのサーバはここからが本番です。
