第 5 章 — ハードコードを実 DB に置き換える

Ch.4 でフロントが動きました。 でも誰がログインしても全員 alice、 全員 id=1 で、 サーバが「誰の操作か」 を知らない状態。 ここからは Ch.4 でハードコードした応答を、 1 つずつ実 DB の中身に差し替えていきます。

2 スパイラルで:

  1. POST /api/register を、 ハードコード応答から 実 INSERTに
  2. POST /api/login を、 ハードコードから 実 SELECT + 照合に
📝 まだやらないこと
  • パスワードハッシュ化 (Ch.6) — ここではまだ平文で保存
  • セッション / Bearer Token (Ch.6) — ここではトークンも返さない
  • ガチャ抽選の本実装 (Ch.7) / Box (Ch.8)

「Web セキュリティ的に正しい状態」 は Ch.6 で揃います。 ここでは「ハードコード → 実 DB」 の置き換え方法に集中。

5.1 ハードコードの何が問題か

Ch.4 末で書いた register ハンドラを思い出すと:

@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = (body.get("name") or "").strip() or "anonymous"
    h._json(200, {"user": {
        "id": 1, "name": name,
        "display_name": body.get("display_name") or name,
        "coins": 1000,
    }})

これが本物のサービスじゃない理由:

  • 誰が登録しても id=1
  • 登録した内容がどこにも保存されない (リロードで消える)
  • 同じ name で何度でも「登録成功」 が返る (= 名前の重複を防げない)
  • ログイン時に「本当にこの人?」 を照合する材料がない

Ch.2 で users テーブルを作って、 Ch.3 で Python から sqlite3 経由で INSERT/SELECT する経験は済んでいます。 これをregister ハンドラの中でやればいい、 というのが今回の課題。

5.2 sqlite 接続ヘルパを Colab で復習

Ch.3 で書いた接続ヘルパ get_conn() をそのまま使います。 まだ生きていれば飛ばして OK、 Colab を再起動した場合は再実行します。

📒 セル 5-A — sqlite 接続 (再掲) 
import sqlite3
from contextlib import contextmanager

DB_PATH = "gacha.db"   # Ch.2 で作った gacha.db を使い回す

@contextmanager
def get_conn():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row    # 結果を辞書ライクにアクセス可能に
    try:
        yield conn
        conn.commit()
    except Exception:
        conn.rollback()
        raise
    finally:
        conn.close()

# 動作確認
with get_conn() as conn:
    cur = conn.execute("SELECT COUNT(*) AS n FROM users")
    print("現時点の users 行数:", cur.fetchone()["n"])

行数が出れば OK。 「no such table: users」 が出る人は、 Colab を再起動した影響で gacha.db が消えたか、 別フォルダで動いている可能性。 Ch.2 の CREATE TABLE セルをもう一度実行してください。

Spiral 1 — register を実 INSERT に置き換える

ハンドラの中身を「users テーブルに INSERT して、 採番された id を返す」 に書き換えます。 Ch.3 で POST /api/users を実装したパターンとほぼ同じ。 違いはエンドポイント名と フロントが期待する shape ({"user": {...}}) を返すこと。

📒 セル 5-B — register を本物に 
@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    password = body.get("password") or ""
    display_name = (body.get("display_name") or "").strip() or name

    # 入力チェック (DB に届く前にやる)
    if len(name) < 3 or len(name) > 32:
        raise bad_request("name は 3〜32 文字")
    if len(password) < 6:
        raise bad_request("password は 6 文字以上")

    # ⚠️ 学習用に password を平文で保存。 Ch.6 でハッシュ化する。
    with get_conn() as conn:
        # 同じ name が既にあるか先に確認 (UNIQUE 制約があれば INSERT でも弾かれるが、
        # アプリ層で先に見て分かりやすいエラーに変えたい)
        cur = conn.execute("SELECT 1 FROM users WHERE name = ?", (name,))
        if cur.fetchone():
            raise bad_request("その name は既に使われています")

        cur = conn.execute(
            """
            INSERT INTO users (name, pass_hash, display_name)
            VALUES (?, ?, ?)
            RETURNING id, name, display_name
            """,
            (name, password, display_name),
        )
        row = dict(cur.fetchone())

    # フロントが期待する shape: {"user": {id, name, display_name, coins}}
    # coins はテーブルに無いので、 学習中は固定値 1000 で返す。 Ch.7 でガチャ実装時に動的に。
    row["coins"] = 1000
    h._json(200, {"user": row})

print("✅ /api/register が実 DB に INSERT するようになった")

💡 解説

  • プレースホルダ ?: SQL に値を埋め込む安全な方法 (詳しくは下のコラムで)
  • RETURNING id, name, display_name: INSERT した行をそのまま返してもらう。 採番された id を別 SELECT する必要がない
  • conn.row_factory = sqlite3.Row のおかげで、 結果が辞書ライクに使える
  • dict(cur.fetchone()) で純粋な dict に変換 → JSON にそのまま入れられる
  • UNIQUE 事前チェックをアプリ層でしているが、 DB の UNIQUE 制約も保険として残っている。 二段構え
📚 コラム: SQL インジェクションと ? プレースホルダ

もし上のコードを書く時、 こうするとどうなるでしょう? 

# ❌ 絶対やってはいけない書き方
cur = conn.execute(f"INSERT INTO users (name, pass_hash, display_name) "
                   f"VALUES ('{name}', '{password}', '{display_name}')")

一見動きます。 でも誰かが name に '); DROP TABLE users; -- という文字列を入れてくると、 結果として実行される SQL は: 

INSERT INTO users (name, pass_hash, display_name)
VALUES ('');
DROP TABLE users;
--', 'pass', 'display');

users テーブルが丸ごと消える。 これが SQL インジェクション。

プレースホルダ (?) を使うと、 ライブラリが文字列を「データ」 として扱い、 SQL 文として解釈されない形でエスケープしてくれる。 だから: 

# ✅ 安全な書き方
cur = conn.execute("INSERT INTO users (name, ...) VALUES (?, ...)",
                   (user_input, ...))

プレースホルダ自体は SQL の方言で書き方が違う:

  • SQLite / Python の sqlite3 モジュール: ?
  • PostgreSQL / Python の psycopg モジュール: %s
  • MySQL / Python の PyMySQL モジュール: %s

記号は違っても役割は同じ: 「文字列連結で SQL を組み立てない」 が鉄則。 Ch.9 でローカルに移って psycopg を使う時、 ? を %s に書き換えるだけで動きます。

ブラウザで開いている学習モードフロントに戻って、 alice / secret123 で「新規登録」 ボタン押下。 画面とデバッグコンソールで:

✅ 期待される結果

  • 画面: ガチャ画面に切り替わる、 「ようこそ alice さん」
  • Colab で %%sql SELECT * FROM users; → alice の行が増えている (= 本物の永続化が起きた)

もう 1 度同じ name で登録しようとすると、 今度はエラーが返るはず:

Spiral 2 — login を実 SELECT + 照合に置き換える

ログインも同じ要領で本物に。 「name で SELECT してきて、 password が一致するかチェック」。 パスワードの照合はまだ平文同士の比較です (= 危険版)。 Ch.6 でハッシュ化に切り替える前提で、 ここではシンプルに進めます。

📒 セル 5-C — login を本物に 
@route("POST", "/api/login")
def login(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    password = body.get("password") or ""

    with get_conn() as conn:
        cur = conn.execute(
            "SELECT id, name, display_name, pass_hash FROM users WHERE name = ?",
            (name,),
        )
        row = cur.fetchone()

    # ⚠️ Ch.6 でハッシュ化に切り替える。 今は平文同士で比較。
    if row is None or row["pass_hash"] != password:
        raise AppError(401, "name か password が違います")

    user = {
        "id": row["id"],
        "name": row["name"],
        "display_name": row["display_name"],
        "coins": 1000,        # Ch.7 で users テーブルから取るようにする
    }
    h._json(200, {"user": user})

print("✅ /api/login が実 DB の users と照合するようになった")

🧪 動作確認

  1. フロントで「ログアウト」 を押す (Ch.4 で実装したハードコード版でも OK)
  2. 登録済みの alice / secret123 でログイン → ✅ ガチャ画面
  3. alice / WRONGPASS でログイン → 401、 「❌ 認証が通りませんでした」
  4. 未登録の bob でログイン → 401

これでようやく「本物のユーザー登録 + ログイン」 になった。 DB に入っている人だけが入れる、 入っていない人は弾かれる。 フロントの動きはほぼ同じ (= shape が変わってないので) でも、 中身は別物に進化しています。

5.3 ハードコードのまま残しているもの

ここまでで register / login は本物に。 でもまだ次の問題が残っている:

API現状本物にするのは
POST /api/register✅ 実 DB INSERT✓ Ch.5 で完了
POST /api/login✅ 実 SELECT + 平文照合パスは Ch.6 でハッシュ化
GET /api/me常に 401Ch.6 で session-aware に
POST /api/logout常に {"ok": true}Ch.6 で session を破棄するように
GET /api/gacha/list固定 2 件Ch.7 で gachas テーブル作って SELECT
POST /api/gacha/pull常にドラゴンCh.7 で重み付き乱択 + 履歴 INSERT
GET /api/box固定 1 件Ch.8 で履歴を集計して返す

1 ハンドラずつ「ハードコード → 実 DB」 のスパイラルを回すのが Ch.5〜8 のリズム。 shape を変えなければフロントは何も気にせず動き続けるので、 安心してハンドラ内部だけ書き換えられます。

本章のまとめ

  • register はハードコード → 実 INSERT になった。 同じ name で 2 度登録は弾かれる
  • login も実 SELECT + 照合に。 登録した人だけがログイン可能
  • プレースホルダ ? を使うと SQL インジェクションを防げる。 SQL 文に値を文字列連結しないのが鉄則
  • shape (応答形式) を維持したままハンドラ内部を進化させる = フロントは無傷
