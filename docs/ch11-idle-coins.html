Chapter 11 所要時間: 90〜120 分 形式: スキーマ拡張 + ヘルパ関数 + 行ロック

第 11 章 — アイドル風コイン自動生成

クッキークリッカーや放置ゲーで定番の「ログインしてない間にも貯まる」 仕組みを足します。 装備しているキャラのレア度合計を 「1 秒あたりに貯まる量」 として、 最後に回収した時刻からの経過秒数に応じてコインを加算する。

🎯 この章のゴール
  1. 装備キャラの多対多テーブル equipped_characters を作る
  2. collect(conn, user_id) ヘルパで「最後の回収から今までの分」 を加算
  3. 行ロック (FOR UPDATE) で並行回収による二重加算を防ぐ
  4. GET /api/me など主要エンドポイントで自動的に collect が走る

実習は exercises/ch11/ の step1〜6 をコピペで上から流していけば組み上がります。

11.1 スキーマ拡張

users テーブルに「最後に回収した時刻」 を持たせ、 装備キャラ用の 多対多テーブルを足します。 

ALTER TABLE users
    ADD COLUMN IF NOT EXISTS last_collected_at TIMESTAMPTZ NOT NULL DEFAULT NOW();

CREATE TABLE IF NOT EXISTS equipped_characters (
    user_id      BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    character_id BIGINT NOT NULL REFERENCES characters(id) ON DELETE RESTRICT,
    PRIMARY KEY (user_id, character_id)
);

設計のポイント

  • last_collected_at の DEFAULT NOW() ← 既存ユーザーは ALTER した瞬間が「最後の回収」 と見なされる。 過去分を遡って配らないという方針。
  • (user_id, character_id) 複合 PK ← 同じキャラを 2 回装備できないことを DB で物理保証。
  • ON DELETE RESTRICT ← キャラマスタを誤って消したら「装備中だから消せない」 とエラーが出る。 マスタを守りたい場合の典型パターン。

11.2 「貯まる量」 をどう計算するか

設計はシンプル: 装備しているキャラの rarity 合計 = 1 秒あたりの取得 coin。 ★5 を 1 体 + ★3 を 1 体装備していれば 1 秒あたり 8 coin。 

SELECT u.coins, u.last_collected_at,
       COALESCE(SUM(c.rarity), 0) AS rate
  FROM users u
  LEFT JOIN equipped_characters ec ON ec.user_id = u.id
  LEFT JOIN characters         c  ON c.id        = ec.character_id
 WHERE u.id = %s
 GROUP BY u.id;

LEFT JOIN + COALESCE がポイント — 装備が 0 体のユーザーでも rate = 0 として 1 行返ってくる。 INNER JOIN にすると 装備 0 のユーザーが行ごと消えてバグになる。

11.3 collect() ヘルパを書く

経過秒数から差分 coin を計算して、 users.coins に加算しつつ last_collected_at を NOW() に更新するヘルパ: 

from datetime import datetime, timezone

def collect(conn, user_id: int) -> int:
    """前回回収から今までの分を加算する。 戻り値は今回加算した量。"""
    with conn.cursor() as cur:
        cur.execute(
            """
            SELECT u.last_collected_at,
                   COALESCE(SUM(c.rarity), 0) AS rate
              FROM users u
              LEFT JOIN equipped_characters ec ON ec.user_id = u.id
              LEFT JOIN characters         c  ON c.id        = ec.character_id
             WHERE u.id = %s
             GROUP BY u.id
             FOR UPDATE OF u
            """,
            (user_id,),
        )
        row = cur.fetchone()
        if row is None:
            return 0
        elapsed = (datetime.now(timezone.utc) - row["last_collected_at"]).total_seconds()
        gained  = int(elapsed * row["rate"])
        if gained > 0:
            cur.execute(
                "UPDATE users "
                "   SET coins = coins + %s, last_collected_at = NOW() "
                " WHERE id = %s",
                (gained, user_id),
            )
        return gained

FOR UPDATE OF u が肝

FOR UPDATE OF u ← この行が無いと、 同じユーザーで 2 リクエストが同時に collect() を呼んだとき、 両方が 同じ last_collected_at を読み取ってしまう。 その結果、 経過秒数が二重カウントされて coin が 2 倍貯まるバグになります。

FOR UPDATE OF u は「この SELECT で読んだ users の行に行ロック」。 もう一方のトランザクションは、 こちらが COMMIT するまで SELECT すら待たされる。 これで「前回時刻を読む → 加算する → 時刻更新」 が原子的に進行する。

⚠️ なぜ FOR UPDATE 単独ではなく OF u なのか

JOIN しているテーブル全部にロックをかけると characters マスタまで ロックされてしまい、 他のユーザーまで巻き込んで遅くなる。 ロック対象を明示することで「自分の users 行だけ」 をロックする。

11.4 既存エンドポイントへの組込み

collect() は「coins を読む側のリクエスト全部の頭で呼ぶ」のがコツ。 具体的には: 

@route("GET", "/api/me")
def me(h):
    with get_conn() as conn:
        user = h.require_user(conn)
        collect(conn, user["id"])             # ← ここで自動加算
        with conn.cursor() as cur:
            cur.execute(
                "SELECT id, name, coins FROM users WHERE id = %s",
                (user["id"],),
            )
            me = cur.fetchone()
    h._json(200, me)

/api/box, /api/gacha/pull, /api/daily/claim など、 coins に関わるすべてのエンドポイントの先頭で同じパターンを呼びます。 呼び忘れ防止のため、 認証ミドルウェアの中で呼んでしまう方が 設計としては綺麗 (実習 step6 ではそこに進化させます)。

11.5 シミュレータで動作確認

scripts/ch11_idle_simulator.py は、 users.last_collected_at を 意図的に過去にずらしてから collect() を呼ぶことで、 「N 秒分のコインがちゃんと貯まる」 を観察できるツールです。 

$ python scripts/ch11_idle_simulator.py --user alice --back 60
last_collected_at を 60 秒前にずらしました
装備合計 rate = 8 coin/sec
collect() を実行...
+480 coin (= 60 sec * 8 coin/sec)
new coins: 1480

11.6 落とし穴まとめ

  • LEFT JOIN + COALESCE で装備 0 体のユーザーも対応する
  • FOR UPDATE OF u を忘れると並行回収で coin が二重加算
  • マスタ (characters) までロックしないよう OF u で対象を絞る
  • collect() は毎リクエスト先頭で呼ぶ。 呼び忘れたエンドポイントは「貯まらない場所」 として読者に直撃
