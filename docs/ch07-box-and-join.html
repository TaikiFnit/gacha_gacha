第 7 章 — Box と JOIN・集計

Ch.6 でガチャを引けるようになった。 でも引いた結果がフロントの「Box」 に 正しく集計されて出てこない (まだハードコード)。 ここでは 所持品一覧 + 集計 を実 DB から組み立てて返すようにします。

3 スパイラルで:

  1. 所持品を キャラごとに COUNT して取り出す
  2. 取得日時の MIN / MAX も同じクエリで取る
  3. 本物のレスポンスに組み立てる + total_pulls も返す

Spiral 1 — 所持キャラを集計する SQL を試す

user_characters 履歴から、 同じキャラを引いた回数を数える。 JOIN characters でキャラ情報も付ける。

📒 ターミナル (psql) 
-- alice (id=1) の所持品を集計
SELECT c.id, c.name, c.rarity, c.emoji, COUNT(*) AS count
  FROM user_characters uc
  JOIN characters       c ON c.id = uc.character_id
 WHERE uc.user_id = 1
 GROUP BY c.id
 ORDER BY c.rarity DESC, c.id;

Ch.6 でしばらくガチャを引いていれば、 引いた分のキャラが行として出るはず。 0 行なら、 もう少し引いてからこの章に進んでください。

Spiral 2 — 取得日時 (初獲得 / 最終獲得) も足す

画面で「初めて手に入れた日」 「最後に増えた日」 を出したいことがあるので、 MIN / MAX も同じ GROUP BY で取ります。

📒 ターミナル (psql) 
SELECT c.id, c.name, c.rarity, c.emoji,
       COUNT(*)            AS count,
       MIN(uc.obtained_at) AS first_obtained_at,
       MAX(uc.obtained_at) AS last_obtained_at
  FROM user_characters uc
  JOIN characters       c ON c.id = uc.character_id
 WHERE uc.user_id = 1
 GROUP BY c.id
 ORDER BY c.rarity DESC, c.id;

💡 解説

  • GROUP BY c.id でキャラごとに行をまとめる。 同じキャラの履歴 N 行が 1 行になる
  • 集計関数 (COUNT / MIN / MAX) は GROUP BY の単位で計算される
  • SELECT c.name はキャラ単位で一意なので OK。 GROUP BY 列以外のカラムを直接書くと PostgreSQL は怒ることがあるが、 c.id が PK なら他のキャラ列 (name/rarity/emoji) は関数従属するので OK (PG の機能依存性検査)

Spiral 3 — ハンドラに本実装を入れる + total_pulls

フロントの shape は { user, total_pulls, items[] }。 集計クエリ + 通算引いた回数 を 1 ハンドラで束ねます。

📝 my_server.py の box ハンドラを書き換え 
@route("GET", "/api/box")
def box(h):
    with get_conn() as conn:
        user = h.require_user(conn)        # Ch.5 で作ったヘルパ
        with conn.cursor() as cur:
            # 集計クエリ
            cur.execute(
                """
                SELECT c.id, c.name, c.rarity, c.emoji,
                       COUNT(*)            AS count,
                       MIN(uc.obtained_at) AS first_obtained_at,
                       MAX(uc.obtained_at) AS last_obtained_at
                  FROM user_characters uc
                  JOIN characters       c ON c.id = uc.character_id
                 WHERE uc.user_id = %s
                 GROUP BY c.id
                 ORDER BY c.rarity DESC, c.id
                """,
                (user["id"],),
            )
            items = cur.fetchall()

            # 通算 pull 回数
            cur.execute(
                "SELECT COUNT(*) AS total_pulls FROM user_characters WHERE user_id = %s",
                (user["id"],),
            )
            total_pulls = cur.fetchone()["total_pulls"]

    h._json(200, {
        "user": user,
        "total_pulls": total_pulls,
        "items": items,
    })

🧪 動作確認

  1. ブラウザでフロント開いてログイン
  2. ガチャを 5〜10 回引く → 引くたびに右下の Box が増えていく
  3. レア度の高い順に並ぶ ← ORDER BY c.rarity DESC が効いている
  4. 同じキャラを複数回引くと右上に ×2 など個数バッジが出る
  5. ページの「最新化」 ボタン押下 → GET /api/box が緑の ✓ で返る

📝 自分でちょっと拡張

  • 「まだ持っていないキャラ」 だけを返す API /api/missing を追加してみる (LEFT JOIN + WHERE uc.id IS NULL)
  • レア度別のコンプリート率を返す API /api/box/completion を追加してみる (CTE + LEFT JOIN + round(count/total*100, 1))

本章のまとめ

  • 履歴テーブル + GROUP BY + 集計関数 = 「現在の状態」 を引き出す王道パターン
  • JOIN でマスタ情報 (キャラ名・レア度・絵文字) と組み合わせて 1 枚に
  • MIN/MAX で「最初」 「最新」 が同じクエリで取れる
  • 本来「(user_id, character_id) ごとの所持数」 という集計列を別に持っても良いが、 履歴行 + 集計クエリ の方がデータが正で、 後から「いつ入手?」 等の 要件追加にも強い (= 正規化した形)
