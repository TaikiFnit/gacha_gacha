Chapter 5 骨子のみ

第 5 章 — パスワードハッシュとユーザー登録

なぜパスワードを平文で保存してはいけないのか、 ハッシュとは何か、ソルトと反復は何のためにあるのかを、 server/auth.py を題材に解きほぐします。

学習目標

  • ハッシュと暗号の違いを説明できる
  • レインボーテーブル攻撃 / 辞書攻撃に対する「ソルト」「反復回数」の役割が言える
  • PBKDF2 / bcrypt / Argon2 の関係をざっくり説明できる
  • hmac.compare_digest でタイミング攻撃に対抗する理由を理解する

扱うトピック

  1. 「もし DB が漏れたら」を考える
  2. SHA-256 を 1 回かけるだけでは弱い理由
  3. ソルトを 1 ユーザーごとに生成する
  4. 反復回数 200,000 はなぜ妥当か (= 体感 10〜100ms 程度)
  5. 保存形式に「アルゴリズムと反復回数」を含めると将来の移行が楽
  6. パスワード強度 (長さ・複雑性) の話

参照コード

  • server/auth.py の hash_password / verify_password
  • server/app.py の POST /api/register

演習の例

  1. 同じパスワードで 2 ユーザー登録 → pass_hash が異なることを確認 (ソルトの効果)
  2. 反復回数を 1,000 / 200,000 / 1,000,000 と変えて所要時間を計測
  3. compare_digest を == に変えてみる (動くが、なぜ危険か)
