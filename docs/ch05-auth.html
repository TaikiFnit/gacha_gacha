第 5 章 — パスワードハッシュとセッション

Ch.4 で残した 3 つの大きな抜けをここで全部直します。

  • ❌ パスワードを平文で DB に保存している (= 漏洩で全員のパスがバレる)
  • ❌ ログインで name 一致だけを見ている (= パスワードを書き間違えても通る)
  • ❌ /api/me と /api/logout がハードコード (= 「誰がログインしているか」 をサーバが本当には知らない)

5 スパイラルで:

  1. パスワードを pbkdf2 でハッシュ化して保存
  2. ログインで verify_password を呼んでパス検証
  3. sessions テーブル + Cookie でセッション発行
  4. /api/me を Cookie からセッションを引く形に
  5. /api/logout で セッションを破棄

Spiral 1 — パスワードを pbkdf2 でハッシュ化

まずパスワードを平文で保存するのをやめます。 暗号は不要。 必要なのは 「同じパスワードからは同じ値が出るが、 ハッシュ値からは元のパスを逆算できない」 関数 = ハッシュ関数。 ただしただの sha256 1 回では弱い (レインボーテーブル攻撃が現実的)。 対策が:

  • ソルト: ユーザーごとにランダムな byte 列を 1 つ作って、 ハッシュに混ぜる
  • 反復回数: 同じハッシュを 200,000 回繰り返して、 ブルートフォースの計算量を増やす

これらを束ねた仕組みが pbkdf2。 Python 標準ライブラリ hashlib に最初から入っています。

📄 server/auth.py (新規) 
"""パスワードハッシュ + セッション (Ch.5 で追加)。"""
from __future__ import annotations
import base64
import hashlib
import hmac
import os
import secrets
from datetime import datetime, timedelta, timezone

# pbkdf2 のパラメータ
_ALGO = "sha256"
_ITER = 200_000
_SALT_BYTES = 16
_DK_BYTES = 32

# セッションの有効期間
SESSION_TTL = timedelta(days=7)


# ----- パスワード ----------------------------------------------------------
def hash_password(password: str) -> str:
    """パスワードをハッシュ化して、 保存用文字列を返す。

    返り値の形式:  pbkdf2_sha256$$$
    """
    salt = os.urandom(_SALT_BYTES)
    dk = hashlib.pbkdf2_hmac(_ALGO, password.encode("utf-8"),
                             salt, _ITER, dklen=_DK_BYTES)
    return "$".join([
        f"pbkdf2_{_ALGO}",
        str(_ITER),
        base64.b64encode(salt).decode(),
        base64.b64encode(dk).decode(),
    ])


def verify_password(password: str, stored: str) -> bool:
    """保存された文字列と入力パスを比較。 タイミング攻撃に強い hmac.compare_digest を使う。"""
    try:
        algo, iter_s, salt_b64, hash_b64 = stored.split("$")
    except ValueError:
        return False
    if not algo.startswith("pbkdf2_"):
        return False
    digest_name = algo.split("_", 1)[1]
    iters = int(iter_s)
    salt = base64.b64decode(salt_b64)
    expected = base64.b64decode(hash_b64)
    actual = hashlib.pbkdf2_hmac(digest_name, password.encode("utf-8"),
                                 salt, iters, dklen=len(expected))
    return hmac.compare_digest(actual, expected)


# ----- セッション (後の Spiral 3 で使う) -----------------------------------
def new_session_token() -> str:
    """十分に長いランダムトークン (256bit, URL-safe)。"""
    return secrets.token_urlsafe(32)


def session_expiry() -> datetime:
    return datetime.now(timezone.utc) + SESSION_TTL

📝 register ハンドラを書き換え

Ch.4 で平文 INSERT していた所を、 ハッシュ後の文字列で INSERT するだけ。

📝 my_server.py の register 
from server.auth import hash_password   # ← ファイル先頭に追加

@route("POST", "/api/register")
def register(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    password = body.get("password") or ""
    display_name = (body.get("display_name") or "").strip() or name

    if len(name) < 3 or len(name) > 32:
        raise bad_request("name は 3〜32 文字")
    if len(password) < 6:
        raise bad_request("password は 6 文字以上")

    pass_hash = hash_password(password)   # ← Ch.4 までは平文だった

    with get_conn() as conn, conn.cursor() as cur:
        cur.execute("SELECT 1 FROM users WHERE name = %s", (name,))
        if cur.fetchone():
            raise bad_request("その name は既に使われています")
        cur.execute(
            """
            INSERT INTO users (name, pass_hash, display_name)
            VALUES (%s, %s, %s)
            RETURNING id, name, display_name, coins
            """,
            (name, pass_hash, display_name),
        )
        user = cur.fetchone()
    h._json(200, {"user": user})

サーバ再起動 → フロントから新規登録。 デバッグコンソールは ✓ 緑のまま (shape は変わらない)。 でも psql で SELECT name, pass_hash FROM users すると、 もう平文では入っていません。

Spiral 2 — login で verify_password を呼ぶ

Ch.4 では「name 一致だけ」 で 200 を返していました。 ハッシュ化したので、 SELECT で pass_hash を持ってきて、 入力パスを verify する 形に。

📝 my_server.py の login 
from server.auth import verify_password   # ← ファイル先頭に追加

@route("POST", "/api/login")
def login(h):
    body = h._read_json()
    name = (body.get("name") or "").strip()
    password = body.get("password") or ""

    with get_conn() as conn, conn.cursor() as cur:
        cur.execute(
            "SELECT id, name, pass_hash, display_name, coins FROM users WHERE name = %s",
            (name,),
        )
        user = cur.fetchone()
    if user is None or not verify_password(password, user["pass_hash"]):
        raise AppError(401, "name か password が違います")
    # pass_hash はクライアントに返さないように除く
    user.pop("pass_hash", None)
    h._json(200, {"user": user})

🧪 動作確認

  • Spiral 1 で登録した alice / secret123 でログイン → ✓ 緑、ガチャ画面に
  • alice / WRONG_PASSWORD でログイン → 401、 「❌ 認証が通りませんでした」
  • 未登録の bob / なんでも → 401
📝 タイミング攻撃って? verify_password は hmac.compare_digest を使っています。 これは 「文字列の長さを揃えて、 一致 or 不一致を出すまでに常に同じ時間がかかる」 比較。 普通の == は最初の不一致 byte で早期 return するので、 攻撃者が レスポンス時間の差分から「この byte までは合っている」 を探れてしまう、 という古典的な微妙攻撃を防ぐためです。

Spiral 3 — sessions テーブル + Cookie でセッション発行

これが認証の本丸。 ログイン成功時にランダムなトークンを発行して sessions テーブルに保存、 同じトークンを Set-Cookie で返す。 クライアント (= 学習モードフロント) は credentials: "include" で fetch するため、 以後のリクエストでは Cookie が自動で付いてきます。

セッション操作を 2 関数にまとめる

📝 server/auth.py の末尾に追加 
def create_session(conn, user_id: int):
    """sessions テーブルにレコードを作って (token, expires_at) を返す。"""
    token = new_session_token()
    expires = session_expiry()
    with conn.cursor() as cur:
        cur.execute(
            "INSERT INTO sessions (token, user_id, expires_at) VALUES (%s, %s, %s)",
            (token, user_id, expires),
        )
    return token, expires


def lookup_session(conn, token: str):
    """token から user 情報を引く。 期限切れ / 不在は None を返す + 期限切れは自動削除。"""
    if not token:
        return None
    with conn.cursor() as cur:
        cur.execute(
            """
            SELECT u.id, u.name, u.display_name, u.coins, s.expires_at
              FROM sessions s
              JOIN users    u ON u.id = s.user_id
             WHERE s.token = %s
            """,
            (token,),
        )
        row = cur.fetchone()
    if row is None:
        return None
    if row["expires_at"] <= datetime.now(timezone.utc):
        delete_session(conn, token)
        return None
    return {k: row[k] for k in ("id", "name", "display_name", "coins")}


def delete_session(conn, token: str) -> None:
    if not token: return
    with conn.cursor() as cur:
        cur.execute("DELETE FROM sessions WHERE token = %s", (token,))

my_server.py に Cookie 用ヘルパ + ハンドラ更新

_json メソッドに set_cookie 引数を増やし、 Cookie を返せるようにします。 加えて、 リクエストの Cookie を読む _cookie ヘルパも追加。

📝 my_server.py の上の方 
import http.cookies
from server.auth import (hash_password, verify_password,
                         create_session, lookup_session, delete_session,
                         SESSION_TTL)

SESSION_COOKIE = "gg_session"

def _make_session_cookie(token):
    jar = http.cookies.SimpleCookie()
    jar[SESSION_COOKIE] = token
    m = jar[SESSION_COOKIE]
    m["path"] = "/"
    m["httponly"] = True
    m["samesite"] = "Lax"
    m["max-age"] = int(SESSION_TTL.total_seconds())
    return jar

def _clear_session_cookie():
    jar = http.cookies.SimpleCookie()
    jar[SESSION_COOKIE] = ""
    m = jar[SESSION_COOKIE]
    m["path"] = "/"; m["httponly"] = True; m["samesite"] = "Lax"; m["max-age"] = 0
    return jar

App クラスの _json を Cookie 受け入れ可能に書き換え + Cookie 読み取り追加:

📝 App クラス内のメソッドを更新 
    def _cookie(self, name):
        raw = self.headers.get("Cookie", "")
        if not raw: return ""
        jar = http.cookies.SimpleCookie()
        jar.load(raw)
        morsel = jar.get(name)
        return morsel.value if morsel else ""

    def _json(self, status, obj, set_cookie=None):       # ← set_cookie を追加
        b = json.dumps(obj, ensure_ascii=False, default=str).encode("utf-8")
        self.send_response(status); self._cors()
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.send_header("Content-Length", str(len(b)))
        if set_cookie is not None:
            for morsel in set_cookie.values():
                self.send_header("Set-Cookie", morsel.OutputString())
        self.end_headers(); self.wfile.write(b)

Spiral 4 — /api/me を Cookie からセッションを引く形に

今までずっとハードコードだった /api/me を、 ようやく本物に。 Cookie からトークンを取り出して、 sessions JOIN users で user 情報を返す。

📝 me ハンドラを書き換え 
@route("GET", "/api/me")
def me(h):
    token = h._cookie(SESSION_COOKIE)
    with get_conn() as conn:
        user = lookup_session(conn, token)
    if user is None:
        raise unauthorized()
    h._json(200, {"user": user})

🧪 動作確認 — ここがクライマックス

  1. ブラウザでフロントを開いて「新規登録」 (alice / secret123)。 ガチャ画面に
  2. ブラウザを完全に閉じて、 もう一度開く
  3. フロントが起動時に GET /api/me を投げる
  4. デバッグコンソールに 200 ✓ 期待形式 が出て、 そのままガチャ画面が出る

これが本物のセッション管理。 ブラウザを再起動しても、 サーバを再起動しても (DB は永続)、 Cookie を消さない限り「あなたは alice」 と覚え続けてくれます。

Spiral 5 — /api/logout でセッション破棄

📝 logout ハンドラを書き換え 
@route("POST", "/api/logout")
def logout(h):
    token = h._cookie(SESSION_COOKIE)
    with get_conn() as conn:
        delete_session(conn, token)
    h._json(200, {"ok": True}, set_cookie=_clear_session_cookie())

🧪 動作確認

  • ガチャ画面で「ログアウト」 ボタン押下 → 登録/ログインフォームに戻る
  • そのままブラウザリロード → 401 が出て登録フォーム維持 (= セッションが消えた)
  • psql で SELECT * FROM sessions → 行が消えている

require_user ヘルパ — 認証が必要なハンドラの共通処理

認証必須のエンドポイントが今後増えます (pull, box)。 共通処理として:

📝 App クラスに追加 
    def require_user(self, conn):
        """認証必須エンドポイントの先頭で呼ぶ。 未認証なら 401 を投げる。"""
        token = self._cookie(SESSION_COOKIE)
        user = lookup_session(conn, token)
        if user is None:
            raise unauthorized()
        return user

これで Ch.6, Ch.7 で user = h.require_user(conn) 一行で済むようになります。

本章のまとめ

  • パスワードはハッシュ化。 ソルトで「同じパスでも違う出力」、 反復で「ブルートフォースを遅く」
  • パス比較は hmac.compare_digest。 タイミング攻撃を防ぐ
  • セッションは「ランダムトークンを DB に保存して Cookie で配る」 だけ (= 暗号も JWT も使わずシンプル)
  • Cookie 属性 HttpOnly + SameSite=Lax で XSS / CSRF を緩和
  • require_user ヘルパで、 認証必須ハンドラの定型句が 1 行に
📝 本番で気をつけたいこと
  • HTTPS 配信時は Cookie に Secure 属性も追加
  • 同じユーザーが複数端末からログインしたときの session 数管理
  • 定期的に DELETE FROM sessions WHERE expires_at < NOW() で掃除
  • パスワードは Argon2 / bcrypt の方が pbkdf2 より望ましい (今回は標準ライブラリで完結させたかった)
